# 08 · 开发、测试与部署

## 1. 环境要求

| 工具 | 版本/说明 |
| --- | --- |
| JDK | 21 |
| Maven | 3.9+ |
| Node.js | 20+；Maven 构建会自动使用 Node v26.13.0 |
| npm | 随 Node 安装 |
| Docker | 可选，用于 PostgreSQL / 生产验证 |
| PostgreSQL | 可选，生产或本地容器 |

当前 Windows 开发环境：

- 项目根目录：`C:\IdeaProject\WebProduce\WebPorduce`。
- 便携 Node：`C:\IdeaProject\WebProduce\.tools\node`。
- PowerShell 中要调用 `npm.cmd`，不要直接调用 `npm`（会命中 `npm.ps1` 被 ExecutionPolicy 阻止）。
- Maven 属性参数需要加引号：`mvn "-Dskip.frontend=true" ...`。

## 2. 本地开发

### 2.1 前后端分开（推荐）

终端 1，启动后端：

```powershell
mvn "-Dskip.frontend=true" spring-boot:run
```

- 端口：`8080`。
- 数据库：H2 文件库 `./data/webporduce`。
- 上传目录：`./data/uploads`。
- 默认 AI：Mock。

终端 2，启动前端：

```powershell
cd frontend
npm.cmd install
npm.cmd run dev
```

- 端口：`5173`。
- `/api` 代理到 `http://localhost:8080`。

打开 `http://localhost:5173`。

### 2.2 后端托管前端构建产物

```powershell
cd frontend
npm.cmd run build
cd ..
mvn "-Dskip.frontend=true" spring-boot:run
```

前端构建输出到 `src/main/resources/static`。打开 `http://localhost:8080`。

**注意**：

- Spring Boot 不会热加载新增的静态资源，构建后需要重启。
- `npm run build` 成功时 PowerShell 仍可能因为 stderr 警告返回退出码 1；以产物和构建日志为准。
- Vite 构建会提示主 chunk 较大，这是当前已知情况。

### 2.3 完整 Maven 构建

```powershell
mvn -B package
```

会依次：

1. 通过 frontend-maven-plugin 安装 Node。
2. `npm install`。
3. `npm run build`，输出到 `src/main/resources/static`。
4. 编译后端。
5. 运行测试。
6. 打包 `target/WebPorduce-0.0.1-SNAPSHOT.jar`。

启动：

```powershell
java -jar target/WebPorduce-0.0.1-SNAPSHOT.jar
```

### 2.4 H2 控制台

```text
http://localhost:8080/h2-console
JDBC URL: jdbc:h2:file:./data/webporduce
User: sa
Password: 留空
```

H2 控制台只在 `dev` 配置启用，生产不要暴露。

| `SESSION_COOKIE_SECURE` | `false` | HTTPS 环境设为 `true` |

## 4. 启用真实 DeepSeek

PowerShell 示例：

```powershell
$env:AI_PROVIDER = "deepseek"
$env:DEEPSEEK_API_KEY = "sk-..."
$env:DEEPSEEK_MODEL = "deepseek-chat"
mvn "-Dskip.frontend=true" spring-boot:run
```

或：

```powershell
java -jar target/WebPorduce-0.0.1-SNAPSHOT.jar `
  --app.ai.provider=deepseek `
  --app.ai.deepseek.api-key=sk-...
```

注意：

- 不要把 Key 提交到仓库。
- 如果 Key 为空，服务会回退 Mock 并记录 warning。
- 如果 DeepSeek 请求失败，服务会降级 Mock，并在回复中说明。

## 7. Docker + PostgreSQL

### 7.1 文件

- `Dockerfile`：三阶段构建。
- `docker-compose.yml`：PostgreSQL + 应用。
- `.dockerignore`：排除 node_modules、target、data 等。
- `.env.example`：环境变量模板。

### 7.2 启动

```bash
cp .env.example .env
# 修改 POSTGRES_PASSWORD，按需配置 AI_PROVIDER / DEEPSEEK_API_KEY
docker compose up --build
```

访问 `http://localhost:8080`。

### 7.3 Dockerfile 结构

```text
Stage 1: node:22-alpine
  COPY frontend/package*.json
  npm ci
  COPY frontend/
  npm run build

Stage 2: maven:3.9-eclipse-temurin-21
  COPY pom.xml
  mvn dependency:go-offline
  COPY src/
  COPY --from=stage1 /workspace/src/main/resources/static
  mvn -DskipTests package

Stage 3: eclipse-temurin:21-jre-alpine
  创建非 root 用户 aster
  COPY jar
  ENV SPRING_PROFILES_ACTIVE=prod
  VOLUME /app/uploads
  EXPOSE 8080
```

### 7.4 Compose 服务

- `db`：`postgres:16-alpine`，带 `pg_isready` healthcheck。
- `app`：依赖 db 健康后启动。
- 数据卷：
  - `postgres_data`
  - `uploads`
- 环境变量来自 `.env`。

## 9. 常见问题

### 9.1 PowerShell 无法执行 npm

现象：`npm.ps1 cannot be loaded because running scripts is disabled`。

解决：使用 `npm.cmd`，或调整 ExecutionPolicy。

### 9.2 Maven 属性参数报错

PowerShell 下使用：

```powershell
mvn "-Dskip.frontend=true" test
```

不要写成未加引号的 `-Dskip.frontend=true`。

### 9.3 前端构建返回退出码 1

如果日志显示构建成功且 `src/main/resources/static` 有产物，通常是 stderr 警告导致 PowerShell 退出码判断异常。以产物为准，必要时执行：

```powershell
cd frontend
npm.cmd run build
echo $LASTEXITCODE
```

### 9.4 修改前端后页面没变

- 确认构建输出到 `src/main/resources/static`。
- 重启 Spring Boot，静态资源不会热加载。
- 检查浏览器缓存。

### 9.5 登录后刷新掉登录

- 检查 Cookie 是否被浏览器阻止。
- 检查 `SameSite` 和 HTTPS 配置。
- 检查后端是否重启（内存 Session 会丢失）。
- 多实例部署需要共享 Session。

### 9.6 上传图片 413

- 单文件限制 8MB，单请求 10MB。
- 检查反向代理的 `client_max_body_size`。
- 检查 `spring.servlet.multipart` 配置。

### 9.7 导出图片缺失

- 图片必须能被当前登录用户访问。
- 上传图片使用 `/api/assets/{id}/content`，导出时会带 Cookie fetch。
- 跨域图片可能被浏览器阻止。
- 检查浏览器控制台网络请求。

### 9.8 DeepSeek 一直使用 Mock

- 检查 `AI_PROVIDER=deepseek`。
- 检查 `DEEPSEEK_API_KEY` 是否为空。
- 检查网络和 Base URL。
- 查看后端日志中的 warning。

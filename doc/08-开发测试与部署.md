# 08 · 开发、测试与部署

## 1. 环境要求

| 工具 | 版本/说明 |
| --- | --- |
| JDK | 21 |
| Maven | 3.9+ |
| Node.js | 20+；Maven 构建会自动使用 Node v26.13.0 |
| npm | 随 Node 安装 |
| Docker | 可选，用于 PostgreSQL / 生产验证 |
| PostgreSQL | 可选，生产或本地容器 |

当前 Windows 开发环境：

- 项目根目录：`C:\IdeaProject\WebProduce\WebPorduce`。
- 便携 Node：`C:\IdeaProject\WebProduce\.tools\node`。
- PowerShell 中要调用 `npm.cmd`，不要直接调用 `npm`（会命中 `npm.ps1` 被 ExecutionPolicy 阻止）。
- Maven 属性参数需要加引号：`mvn "-Dskip.frontend=true" ...`。

## 2. 本地开发

### 2.1 前后端分开（推荐）

终端 1，启动后端：

```powershell
mvn "-Dskip.frontend=true" spring-boot:run
```

- 端口：`8080`。
- 数据库：H2 文件库 `./data/webporduce`。
- 上传目录：`./data/uploads`。
- 默认 AI：Mock。

终端 2，启动前端：

```powershell
cd frontend
npm.cmd install
npm.cmd run dev
```

- 端口：`5173`。
- `/api` 代理到 `http://localhost:8080`。

打开 `http://localhost:5173`。

### 2.2 后端托管前端构建产物

```powershell
cd frontend
npm.cmd run build
cd ..
mvn "-Dskip.frontend=true" spring-boot:run
```

前端构建输出到 `src/main/resources/static`。打开 `http://localhost:8080`。

**注意**：

- Spring Boot 不会热加载新增的静态资源，构建后需要重启。
- `npm run build` 成功时 PowerShell 仍可能因为 stderr 警告返回退出码 1；以产物和构建日志为准。
- Vite 构建会提示主 chunk 较大，这是当前已知情况。

### 2.3 完整 Maven 构建

```powershell
mvn -B package
```

会依次：

1. 通过 frontend-maven-plugin 安装 Node。
2. `npm install`。
3. `npm run build`，输出到 `src/main/resources/static`。
4. 编译后端。
5. 运行测试。
6. 打包 `target/WebPorduce-0.0.1-SNAPSHOT.jar`。

启动：

```powershell
java -jar target/WebPorduce-0.0.1-SNAPSHOT.jar
```

### 2.4 H2 控制台

```text
http://localhost:8080/h2-console
JDBC URL: jdbc:h2:file:./data/webporduce
User: sa
Password: 留空
```

H2 控制台只在 `dev` 配置启用，生产不要暴露。

### 2.5 本地 PostgreSQL

项目提供独立的 `local-postgres` profile：

- 基础配置：`src/main/resources/application-local-postgres.yaml`
- 本地密码文件：`config/application-local-postgres.yaml`（已被 `.gitignore` 忽略）
- 模板：`config/application-local-postgres.yaml.example`
- IntelliJ 运行配置：`.run/WebPorduce PostgreSQL.run.xml`

把 `config/application-local-postgres.yaml` 里的 `password` 改成你的 PostgreSQL 密码，然后在 IntelliJ 中选择 `WebPorduce PostgreSQL` 运行即可。

本地 PostgreSQL 不需要 `APP_AI_ENCRYPTION_KEY`。`local-postgres` 不是 `prod`，未设置加密 Key 时会使用开发回退密钥。

首次启动时 Flyway 会自动创建表。H2 旧数据不会自动迁移。

## 3. 环境变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `SPRING_PROFILES_ACTIVE` | `dev` | `dev`（H2）/ `local-postgres`（本地 PostgreSQL）/ `prod`（生产） |
| `SERVER_PORT` | `8080` | 服务端口 |
| `DB_URL` | `jdbc:postgresql://localhost:5432/webporduce` | 生产数据库 |
| `DB_USERNAME` | `webporduce` | 数据库用户 |
| `DB_PASSWORD` | 见 `config/application-local-postgres.yaml` | 数据库密码；`local-postgres` 优先读本地 YAML |
| `APP_STORAGE_ROOT` | `./data/uploads` | 上传目录 |
| `APP_AI_ENCRYPTION_KEY` | 空（开发有内置回退） | 用户 AI Key 加密密钥，生产必填，至少 16 字符 |
| `AI_PROVIDER` | `mock` | `mock` 或 `deepseek`（服务端兜底） |
| `DEEPSEEK_API_KEY` | 空 | 服务端 DeepSeek 兜底 Key |
| `DEEPSEEK_BASE_URL` | `https://api.deepseek.com` | 兼容接口 |
| `DEEPSEEK_MODEL` | `deepseek-chat` | 模型名 |
| `SEED_DEMO` | `true` | 注册时创建示例项目 |
| `SESSION_COOKIE_SECURE` | `false` | HTTPS 环境设为 `true` |

## 4. 配置用户 AI 与服务端兜底

### 4.1 在界面中配置（推荐）

1. 登录后打开 `#/settings/ai`。
2. 点击「添加 AI」。
3. 选择协议，填写 Base URL、模型名和 API Key。
4. 点击「测试连接」，确认模型能返回 JSON。
5. 保存并设为默认。

之后所有项目的对话都会优先使用这套配置。配置只属于当前用户，列表接口只返回 Key 末四位。

本地 Ollama 示例：

```text
协议：OpenAI 兼容
Base URL：http://localhost:11434/v1
模型：qwen2.5:7b
API Key：留空
```

DeepSeek 示例：

```text
协议：OpenAI 兼容
Base URL：https://api.deepseek.com
模型：deepseek-chat
API Key：sk-...
```

### 4.2 生产加密密钥

用户 API Key 使用 AES-GCM 加密。`APP_AI_ENCRYPTION_KEY` 是服务端主密钥，不是用户 AI 配置的重复项：

- 用户填的是调用模型服务的 API Key。
- 服务端用 `APP_AI_ENCRYPTION_KEY` 把所有用户的 API Key 加密后落库。
- 本地 `dev` / `local-postgres` 不设置也能启动，会使用开发回退密钥。
- 只有生产 `prod` 必须设置，否则启动失败。

生产环境必须设置：

```bash
APP_AI_ENCRYPTION_KEY=your-random-secret-at-least-16-chars
```

注意：

- 至少 16 个字符，建议使用密码管理器生成 32 字节以上随机值。
- 更换密钥后，旧密文无法解密，需要用户重新保存 API Key。
- 不要把密钥提交到 Git，也不要写入镜像。
- Docker Compose 已要求 `.env` 提供该变量。

### 4.3 服务端 DeepSeek 兜底

用户没有默认配置时，可以继续使用服务端 DeepSeek：

```powershell
$env:AI_PROVIDER = "deepseek"
$env:DEEPSEEK_API_KEY = "sk-..."
$env:DEEPSEEK_MODEL = "deepseek-chat"
mvn "-Dskip.frontend=true" spring-boot:run
```

注意：

- 用户配置优先于服务端兜底。
- 服务端兜底优先于 Mock。
- 如果 Key 为空，服务会回退 Mock 并记录 warning。
- 如果模型请求失败，服务会降级 Mock，并在回复中说明。

### 7.3 Dockerfile 结构

```text
Stage 1: node:22-alpine
  COPY frontend/package*.json
  npm ci
  COPY frontend/
  npm run build

Stage 2: maven:3.9-eclipse-temurin-21
  COPY pom.xml
  mvn dependency:go-offline
  COPY src/
  COPY --from=stage1 /workspace/src/main/resources/static
  mvn -DskipTests package

Stage 3: eclipse-temurin:21-jre-alpine
  创建非 root 用户 aster
  COPY jar
  ENV SPRING_PROFILES_ACTIVE=prod
  VOLUME /app/uploads
  EXPOSE 8080
```

### 7.4 Compose 服务

- `db`：`postgres:16-alpine`，带 `pg_isready` healthcheck。
- `app`：依赖 db 健康后启动。

## 9. 常见问题

### 9.1 PowerShell 无法执行 npm

现象：`npm.ps1 cannot be loaded because running scripts is disabled`。

解决：使用 `npm.cmd`，或调整 ExecutionPolicy。

### 9.2 Maven 属性参数报错

PowerShell 下使用：

```powershell
mvn "-Dskip.frontend=true" test
```

不要写成未加引号的 `-Dskip.frontend=true`。

### 9.3 前端构建返回退出码 1

如果日志显示构建成功且 `src/main/resources/static` 有产物，通常是 stderr 警告导致 PowerShell 退出码判断异常。以产物为准，必要时执行：

```powershell
cd frontend
npm.cmd run build
echo $LASTEXITCODE
```

### 9.4 修改前端后页面没变

- 确认构建输出到 `src/main/resources/static`。
- 重启 Spring Boot，静态资源不会热加载。
- 检查浏览器缓存。

### 9.5 登录后刷新掉登录

- 检查 Cookie 是否被浏览器阻止。
- 检查 `SameSite` 和 HTTPS 配置。
- 检查后端是否重启（内存 Session 会丢失）。
- 多实例部署需要共享 Session。

### 9.6 上传图片 413

- 单文件限制 8MB，单请求 10MB。
- 检查反向代理的 `client_max_body_size`。
- 检查 `spring.servlet.multipart` 配置。

### 9.7 导出图片缺失

- 图片必须能被当前登录用户访问。
- 上传图片使用 `/api/assets/{id}/content`，导出时会带 Cookie fetch。
- 跨域图片可能被浏览器阻止。
- 检查浏览器控制台网络请求。

### 9.8 AI 一直使用 Mock

- 到 `#/settings/ai` 检查是否有默认配置。
- 点击「测试连接」，确认 Base URL、模型名和 Key。
- 检查 `APP_AI_ENCRYPTION_KEY` 是否在启动后发生变化；变化会导致旧 Key 无法解密。
- 如果使用服务端兜底，检查 `AI_PROVIDER=deepseek` 和 `DEEPSEEK_API_KEY`。
- 查看后端日志中的 warning。

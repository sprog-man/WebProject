# 01 · 产品方案

## 1. 产品定位

### 1.1 一句话

Aster 是一个 AI 原生页面工作台：先用自然语言生成一版可展示的前端页面，再像编辑设计稿一样直接点选文字、图片、颜色和布局进行修改。

### 1.2 解决的问题

传统 AI 页面生成存在两个明显问题：

1. **每次微调都重新生成整页**：改一个标题或一个颜色，也可能导致其他文案、结构和图片被意外改掉。
2. **生成结果不可控**：直接生成 HTML 很难保证结构、响应式、可访问性和后续可维护性。

Aster 的解决方式：

- AI 只输出结构化的 `PageSpec`，不直接输出 HTML。
- 页面由固定组件库渲染，结构、响应式和样式可控。
- 第一版由 AI 生成，后续修改优先走用户手工编辑或 AI 局部 Patch。
- 编辑器和静态导出复用同一套 React 渲染器。

### 1.3 产品价值

- **更快开始**：一句话得到能看的页面，而不是从空白画布开始。
- **更稳地迭代**：改文字、换图、调颜色不需要重新描述整页。
- **更可控的成品**：固定组件 + 设计变量，避免任意 HTML 带来的质量波动。
- **更低的迁移成本**：导出静态页面，可直接部署到静态托管。
- **可以用自己的 AI**：支持用户自带 OpenAI 兼容 / Anthropic / Gemini 服务，不锁定单一模型。

## 2. 目标用户

### 2.1 核心用户

- 独立设计师、创意工作室：需要快速做品牌官网/作品集首版。
- 创业者、小团队：没有专职前端，需要快速上线落地页。
- 市场/运营人员：需要反复调整标题、图片、颜色和区块。
- AI 产品探索者：希望体验「生成 + 可编辑」的完整闭环。

### 2.2 用户任务

| 用户任务 | 产品响应 |
| --- | --- |
| 我只有一个模糊想法 | 用对话描述品牌、气质和目标，AI 生成首版 |
| 我想改一句话 | 直接点文字改，或在属性面板输入 |
| 我想换一张图 | 点图片，选内置素材或上传自己的图 |
| 我想整体更暖/更冷 | 改主题模式、强调色、字体和字号 |
| 我不想重新生成整页 | AI 编辑模式只返回局部 Patch |
| 我想把页面发出去 | 导出 `index.html + assets/` ZIP |
| 我怕改坏 | 撤销/重做、自动保存、保存状态提示 |

## 3. 产品范围

### 3.1 MVP 范围

首版聚焦 **响应式单页营销官网 / 落地页**，包含：

- 邮箱密码注册、登录、退出。
- 项目列表、新建、打开、重命名、删除。
- 对话生成第一版页面。
- 用户级 AI 配置：OpenAI 兼容 / Anthropic / Gemini，可设默认。
- AI 局部修改页面。
- 画布直接编辑文字和图片。
- 内容、样式、图片、布局四个属性面板。
- 桌面、平板、手机三种预览宽度。
- 自动保存、撤销/重做、保存状态。
- 图片上传与内置图片。
- 静态页面导出。
- H2 本地开发、PostgreSQL 生产配置、Flyway 迁移、Docker 配置。

### 3.2 首版组件范围

只支持 6 类受控组件：

1. `nav.basic` 顶部导航
2. `hero.split` 首屏
3. `gallery.grid` 作品/图片网格
4. `stats.row` 数据条
5. `cta.banner` 行动号召
6. `footer.basic` 页脚

不开放任意 HTML、脚本、第三方组件或自由拖拽布局。

### 3.3 明确不做

- 任意 HTML / CSS / JavaScript 自由生成。
- 自由拖拽式画布和绝对定位布局。
- 多页站点、路由配置、CMS 内容集。
- 第三方登录、团队空间、权限角色。
- 多人实时协作、评论、审批流。
- 模板市场、计费、订阅。
- 服务端 Puppeteer 截图或服务端打包导出。
- 真实表单提交、支付、埋点等业务能力。

## 4. 核心用户流程

### 4.1 首次进入

```text
打开产品
  → 注册账号
  → 自动获得一个示例项目（可配置关闭）
  → 进入工作台
  → 打开示例或新建页面
```

### 4.2 从空白生成第一版

```text
新建页面（空白 PageSpec）
  → 进入编辑器
  → 在对话面板描述品牌/页面/气质
  → 后端判断页面为空，走生成模式
  → AI 返回完整 PageSpec
  → 校验并保存
  → 画布出现第一版
```

### 4.3 手工精修

```text
点击画布文字/图片
  → 选中字段
  → 行内编辑，或打开属性面板
  → 修改 PageSpec
  → 900ms 防抖自动保存
  → 保存成功后更新版本号
```

### 4.4 AI 局部修改

```text
用户输入“把标题更大一点”
  → 前端先确保当前草稿已保存
  → 后端判断页面非空，走编辑模式
  → AI 返回 JSON Patch
  → 后端应用 Patch
  → 校验 PageSpec
  → 更新项目并记录 AI 快照
  → 前端替换画布，保留其他字段
```

### 4.5 导出

```text
点击“导出静态页”
  → 若未保存则先保存
  → 收集页面中所有图片
  → 下载图片写入 assets/
  → 使用 PageRenderer 生成静态 HTML
  → 内联 page.css
  → JSZip 打包
  → 浏览器下载 ZIP
```

## 6. 体验原则

1. **先出结果，再精修**：不要让用户先配置一堆参数。
2. **所有修改都可见**：改完立刻反映到画布。
3. **AI 修改要克制**：只动用户要求的字段。
4. **手工修改优先**：用户改过的内容不应被 AI 无意覆盖。
5. **保存是默认行为**：用户不需要记得点保存。
6. **失败要可恢复**：撤销、重做、错误提示和版本冲突提示。
7. **导出即成品**：导出结果不依赖编辑器运行时。

## 8. 成功指标建议

MVP 阶段建议关注：

- 首次生成完成率：新建项目后发出第一条消息的比例。
- 首次生成满意度：生成后 10 分钟内是否发生手工修改。
- 编辑留存：创建后 7 天内再次打开项目的比例。
- 导出转化：有内容的项目中点击导出的比例。
- AI 修改接受率：AI 修改后是否继续手工修改或撤销。
- 保存失败率、AI 失败率、导出失败率。

## 9. 后续产品方向

### 阶段 1：把 MVP 做稳

- 窄屏和主流浏览器回归。
- 真实 DeepSeek 提示词调优。
- 版本历史 UI 与恢复。
- 保存冲突的可视化处理。
- E2E 测试、错误监控、限流。

### 阶段 2：提升页面生产力

- 更多受控组件：定价表、FAQ、评价、团队、Logo 墙。
- 多页面站点与页面间导航。
- 模板库和品牌套件。
- 服务端导出、图片 CDN/对象存储。
- 自定义字体和更完整的设计变量。

### 阶段 3：团队与商业化

- 团队空间、角色权限、评论审批。
- 模板市场、订阅计费。
- 多人实时协作。
- 自定义组件/插件机制。

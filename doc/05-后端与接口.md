# 05 · 后端与接口

## 1. 后端职责

后端是「页面数据、用户、权限、AI 编排」的可信层，主要职责：

- 用户注册、登录、Session 和 CSRF。
- 项目和页面数据持久化。
- 校验 PageSpec，阻止非法组件和非法主题值。
- 保存用户级 AI 配置，加密 API Key，并选择默认 Provider。
- 调用用户 AI / 服务端兜底 / Mock，解析 AI 结果并应用局部 Patch。
- 维护项目乐观锁版本和 AI 修改快照。
- 保存对话消息。
- 图片上传、元数据和鉴权读取。
- 为前端提供 JSON API，为生产提供静态资源托管。

后端不负责 HTML 渲染和 ZIP 打包；静态导出在浏览器端完成。

## 3. 启动与配置

### 3.1 默认配置

`application.yaml`：

- 默认 profile：`dev`。
- 端口：`8080`。
- Session 有效期：`7d`。
- Session Cookie：`http-only=true`、`same-site=lax`。
- 上传文件：单文件 8MB，单请求 10MB。
- 上传目录：`APP_STORAGE_ROOT`，默认 `./data/uploads`。
- AI Provider：`AI_PROVIDER`，默认 `mock`，作为服务端兜底。
- 用户 AI Key 加密密钥：`APP_AI_ENCRYPTION_KEY`；开发环境可缺省，生产必须设置。
- 示例数据：`SEED_DEMO`，默认 `true`。

### 3.2 Profile

| Profile | 用途 | 数据库 |
| --- | --- | --- |
| `dev` | 本地开发 | H2 文件库 `./data/webporduce` |
| `test` | 自动化测试 | H2 内存库 |
| `prod` | Docker / 生产 | PostgreSQL |

### 3.3 生产配置

`application-prod.yaml`：

- `DB_URL`、`DB_USERNAME`、`DB_PASSWORD` 配置 PostgreSQL。
- Hibernate `ddl-auto=validate`，表结构只由 Flyway 管理。
- 开启 HTTP 压缩。
- 支持反向代理 forwarded headers。
- `SESSION_COOKIE_SECURE` 控制 Cookie Secure，HTTPS 环境应设为 `true`。
- 上传目录默认 `/app/uploads`。

## 4. 请求约定

### 4.1 认证

- 登录成功后，服务端通过 `SecurityContextRepository` 将认证信息写入 HttpSession。
- 浏览器自动携带 `JSESSIONID`。
- 受保护接口从 `CurrentUser.require()` 取当前用户 id。
- 未登录访问 `/api/**` 返回 `401`。

### 4.2 CSRF

- 使用 `CookieCsrfTokenRepository.withHttpOnlyFalse()`。
- Token 同时写入 Cookie 和 `/api/auth/csrf` 响应。
- 前端从 Cookie `XSRF-TOKEN` 读取，并放入请求头 `X-XSRF-TOKEN`。
- 所有非 GET/HEAD/OPTIONS 请求必须带 CSRF。
- `/h2-console/**` 忽略 CSRF，仅开发使用。
- `/api/auth/csrf`、`/api/auth/register`、`/api/auth/login`、`/api/health` 允许匿名。

### 4.3 JSON 与错误

正常响应为 JSON。错误格式：

```json
{
  "code": "VALIDATION_ERROR",
  "message": "请输入页面名称",
  "timestamp": "2026-11-10T08:00:00Z"
}
```

| 字段 | 说明 |
| --- | --- |
| `code` | 机器可读错误码 |
| `message` | 中文用户提示 |
| `timestamp` | 服务端时间 |

### 4.4 状态码

| 状态码 | 场景 |
| --- | --- |
| `200` | 查询/更新成功 |
| `201` | 注册成功、项目创建成功 |
| `204` | 删除项目、退出登录成功 |
| `400` | 参数校验失败、PageSpec 非法、图片类型错误 |
| `401` | 未登录、登录失败 |
| `403` | CSRF 失败、无权限 |
| `404` | 项目/图片不存在 |
| `409` | 邮箱已注册、项目版本冲突 |
| `413` | 上传文件超过限制 |
| `500` | 未预期异常 |
| `502` | AI Patch 非法（部分路径） |

## 6. 认证接口

### 6.1 获取 CSRF

```http
GET /api/auth/csrf
```

响应：

```json
{
  "token": "...",
  "headerName": "X-XSRF-TOKEN",
  "parameterName": "_csrf"
}
```

同时设置 `XSRF-TOKEN` Cookie。

### 6.2 注册

```http
POST /api/auth/register
Content-Type: application/json
X-XSRF-TOKEN: ...

{
  "email": "user@example.com",
  "password": "password123",
  "displayName": "Aster 用户"
}
```

规则：

- 邮箱必须合法，统一转小写并 trim。
- 密码 8–72 位。
- 昵称必填，最长 40。
- 邮箱已存在返回 `409`。
- 注册成功后自动建立 Session。
- 如果 `SEED_DEMO=true`，首次注册且没有项目时创建一个示例项目。

响应 `201`：

```json
{
  "id": "uuid",
  "email": "user@example.com",
  "displayName": "Aster 用户",
  "createdAt": "2026-11-10T08:00:00Z"
}
```

### 6.3 登录

```http
POST /api/auth/login
Content-Type: application/json
X-XSRF-TOKEN: ...

{
  "email": "user@example.com",
  "password": "password123"
}
```

成功返回用户信息。失败统一返回 `401`「邮箱或密码不正确」，避免泄露账号是否存在。

### 6.4 当前用户

```http
GET /api/auth/me
```

返回：

```json
{
  "id": "uuid",
  "email": "user@example.com",
  "displayName": "Aster 用户",
  "createdAt": null
}
```

`me` 和 `login` 的 `createdAt` 当前返回 `null`，只有注册响应会带创建时间。

### 6.5 退出

```http
POST /api/auth/logout
X-XSRF-TOKEN: ...
```

使用 `SecurityContextLogoutHandler` 清理上下文和 Session，返回 `204`。

## 7. 项目接口

### 7.1 列表

```http
GET /api/projects
```

按 `updatedAt DESC` 返回当前用户项目：

```json
[
  {
    "id": "uuid",
    "name": "Aurora 品牌官网",
    "version": 7,
    "spec": { "version": 1, "meta": {}, "theme": {}, "sections": [] },
    "createdAt": "2026-11-10T08:00:00Z",
    "updatedAt": "2026-11-10T09:00:00Z"
  }
]
```

列表只返回摘要结构，但目前也包含完整 `spec`，用于工作台缩略图渲染。

### 7.2 新建

```http
POST /api/projects

{
  "name": "新页面"
}
```

- 名称必填，最长 120。
- 创建 `blankSpec(name)`：有 meta/theme，`sections` 为空。
- 自动写入一条助手欢迎消息。
- 返回 `201` + `ProjectDetail`。

### 7.3 详情

```http
GET /api/projects/{projectId}
```

```json
{
  "id": "uuid",
  "name": "Aurora 品牌官网",
  "version": 7,
  "spec": {},
  "messages": [
    {
      "id": "uuid",
      "role": "assistant",
      "content": "先做了一版……",
      "revisionNumber": 1,
      "createdAt": "2026-11-10T08:00:00Z"
    }
  ],
  "latestRevision": 1,
  "createdAt": "2026-11-10T08:00:00Z",
  "updatedAt": "2026-11-10T09:00:00Z"
}
```

- 消息按 `createdAt ASC` 返回。
- `latestRevision` 是最新 AI 快照号，没有则为 `null`。
- 只能访问自己的项目；其他用户的项目返回 `404`，不暴露存在性。

### 7.4 重命名

```http
PATCH /api/projects/{projectId}

{
  "name": "新的项目名"
}
```

- 名称 trim 后不能为空，最长 120。
- 返回 `ProjectSummary`。
- 重命名也会让 JPA `updatedAt` 更新和版本自增。

### 7.5 删除

```http
DELETE /api/projects/{projectId}
```

- 返回 `204`。
- 数据库通过外键级联删除 `project_revision` 和 `chat_message`。
- `asset.project_id` 为 `ON DELETE SET NULL`，图片元数据不随项目删除，物理文件也不会自动删除。

## 8. 草稿保存

```http
PUT /api/projects/{projectId}/draft

{
  "spec": { "version": 1, "meta": {}, "theme": {}, "sections": [] },
  "version": 7
}
```

`version` 是前端加载时拿到的项目版本号，不是 `spec.version`。

处理流程：

```text
requireOwned(ownerId, projectId)
  → 检查 project.version == expectedVersion
  → PageSpecValidator.validate(spec)
  → project.updateSpec(json)
  → saveAndFlush：JPA @Version +1
  → 返回新版本和 updatedAt
```

成功：

```json
{
  "version": 8,
  "updatedAt": "2026-11-10T09:10:00Z"
}
```

失败：

```json
{
  "code": "VERSION_CONFLICT",
  "message": "页面已在别处更新，请刷新后重试",
  "timestamp": "..."
}
```

HTTP `409`。

**注意**：手工保存不会写入 `project_revision`，目前只有 AI 修改会产生快照。

## 9. 对话接口

```http
POST /api/projects/{projectId}/messages

{
  "content": "把标题更大一点"
}
```

规则：

- 内容必填，最长 4000。
- 先保存一条用户消息。
- 页面为空 → 生成模式。
- 内容包含「重新生成」「换一版」「重做」→ 生成模式。
- 其他 → 编辑模式，AI 返回 Patch。
- AI 调用使用当前用户的默认 AI 配置；没有配置时使用服务端兜底，再没有则 Mock。
- 用户配置调用失败 → Mock 兜底，助手回复说明本次是本地演示模式。
- AI 结果通过校验后更新项目，项目版本自增。
- 如果发生改动，写入 `project_revision`，source 为 `AI`。
- 写入助手消息；如果改动，助手消息带 `revisionNumber`。

响应：

```json
{
  "userMessage": {
    "id": "uuid",
    "role": "user",
    "content": "把标题更大一点",
    "revisionNumber": null,
    "createdAt": "..."
  },
  "assistantMessage": {
    "id": "uuid",
    "role": "assistant",
    "content": "已经同步到画布：标题字号 110%。",
    "revisionNumber": 3,
    "createdAt": "..."
  },
  "spec": {},
  "version": 9,
  "revisionNumber": 3,
  "changed": true
}
```

### 9.1 事务边界

- `prepare` 事务：校验项目归属、写用户消息、读取当前 spec。
- AI 调用发生在事务之外，避免长时间占用数据库连接。
- `complete` 事务：重新读取项目、校验、更新 spec、写快照、写助手消息。

### 9.2 已知并发问题

对话接口没有接收 `expectedVersion`。如果用户在两个标签页同时操作：

- 标签页 A 修改并保存。
- 标签页 B 基于旧页面发 AI 请求。
- 后端在 `complete` 时读取的是数据库最新项目，可能把 A 的修改覆盖。

前端已通过「发送前先保存当前草稿」降低风险，但没有完全消除多标签并发。后续应在消息请求中增加基线版本校验。

## 10. AI 配置接口

所有接口都要求登录，并且只能操作当前用户自己的配置。

### 10.1 Provider 预设

```http
GET /api/ai/providers
```

响应：

```json
[
  {
    "type": "OPENAI_COMPATIBLE",
    "label": "OpenAI 兼容",
    "defaultBaseUrl": "https://api.openai.com/v1",
    "defaultModel": "gpt-4o-mini",
    "description": "适用于 OpenAI、DeepSeek、Moonshot、通义千问、智谱、OpenRouter、Groq、Ollama、vLLM 等服务"
  }
]
```

当前固定返回 `OPENAI_COMPATIBLE`、`ANTHROPIC`、`GEMINI` 三项。

### 10.2 列表

```http
GET /api/ai/configs
```

只返回脱敏字段：

```json
[
  {
    "id": "uuid",
    "name": "我的 DeepSeek",
    "providerType": "OPENAI_COMPATIBLE",
    "baseUrl": "https://api.deepseek.com",
    "model": "deepseek-chat",
    "keyHint": "1234",
    "hasApiKey": true,
    "defaultConfig": true,
    "createdAt": "...",
    "updatedAt": "..."
  }
]
```

不返回 `apiKeyEncrypted` 或明文 Key。

### 10.3 新增 / 更新

```http
POST /api/ai/configs
PUT /api/ai/configs/{configId}
Content-Type: application/json

{
  "name": "我的 DeepSeek",
  "providerType": "OPENAI_COMPATIBLE",
  "baseUrl": "https://api.deepseek.com",
  "model": "deepseek-chat",
  "apiKey": "sk-...",
  "defaultConfig": true
}
```

规则：

- `name` 最长 80，`baseUrl` 最长 500，`model` 最长 160。
- Base URL 必须以 `http://` 或 `https://` 开头，尾部 `/` 会被去掉。
- 新增时如果用户还没有任何配置，会自动设为默认。
- 更新时 `apiKey` 留空表示保留原 Key。
- 设置新的默认配置时，会先清除同一用户的其他默认标记。
- 取消默认时，会自动把最早创建的另一个配置设为默认。

### 10.4 设置默认 / 删除

```http
POST /api/ai/configs/{configId}/default
DELETE /api/ai/configs/{configId}
```

- 设置默认是幂等的。
- 删除默认配置后，会自动把剩余最早创建的配置设为默认。
- 删除不存在的配置返回 `404 AI_CONFIG_NOT_FOUND`。

### 10.5 测试连接

```http
POST /api/ai/configs/{configId}/test
```

发送一次最小 JSON 输出请求，不会修改项目或写入对话。

响应：

```json
{
  "ok": false,
  "message": "无法连接模型服务",
  "latencyMs": 28,
  "model": "deepseek-chat"
}
```

### 10.6 加密与降级

- API Key 使用 AES-GCM 加密，密钥由 `APP_AI_ENCRYPTION_KEY` 派生。
- 生产环境启动时缺少密钥会直接失败。
- 对话时优先使用默认配置；加载配置或调用模型失败时降级 Mock，并在助手回复中说明。
- 测试连接失败不会影响已有页面和编辑器。

### 10.7 图像 AI 配置与图片生成

图像 AI 配置独立于文本 AI 配置，保存于 `image_ai_config` 表，接口前缀为 `/api/image-ai`。

**协议与字段**

| 字段 | 说明 |
| --- | --- |
| `providerType` | 首版只有 `OPENAI_IMAGES`，兼容 OpenAI Images 协议 |
| `baseUrl` | 可填完整 `/images/generations` 端点，也可填 `/v1` 基础地址 |
| `model` | 图像模型 ID，例如 `agnes-image-2.5-flash` |
| `apiKeyEncrypted` | 与文本 AI 共用 AES-GCM 加密服务 |
| `apiKeyHint` | 只返回末四位 |
| `defaultSize` | `512x512` / `1024x1024` / `1024x1536` / `1536x1024` |
| `defaultQuality` | 可选，留空不发送 |

新增时如果没有其他配置，会自动设为默认；设置新默认会清除同用户其他默认；删除默认后按创建时间自动切换。更新时 `apiKey` 留空表示保留原 Key。

**测试连接**

`POST /api/image-ai/configs/{id}/test` 会真实生成一张 1:1 测试图（可能产生费用），把图片保存为 `source=AI_TEST` 的资产，并返回：

```json
{
  "ok": true,
  "message": "连接成功，测试图片已真实生成。可以在卡片上查看预览。",
  "latencyMs": 4200,
  "model": "agnes-image-2.5-flash",
  "size": "1024x1024",
  "previewUrl": "/api/assets/{assetId}/content",
  "mimeType": "image/png",
  "width": 1024,
  "height": 1024
}
```

失败时 `ok=false`，`message` 保留真实 HTTP 状态或连接错误，不返回 API Key。测试图不写入任何项目。

**图片任务**

`POST /api/projects/{projectId}/image-jobs`

```json
{
  "items": [
    {
      "sectionId": "hero",
      "path": "props.image",
      "prompt": "Editorial coffee brand photography..."
    }
  ]
}
```

规则：

- 必须已登录并且项目属于当前用户。
- 必须有默认图像 AI，否则返回 `IMAGE_AI_NOT_CONFIGURED`。
- 一次最多 5 张；只处理请求中明确列出的图片，未勾选的图片不会生成。
- `path` 只允许 `props.image` 或 `props.items.N.image`。
- 服务端从数据库当前 PageSpec 中查找目标，找不到返回 `IMAGE_TARGET_NOT_FOUND`。
- `prompt` 为空时使用图片自身的 `prompt`；仍为空返回 `IMAGE_PROMPT_REQUIRED`。
- 同一 `targetPath` 已有 PENDING/RUNNING 任务时返回 `409 IMAGE_JOB_ALREADY_RUNNING`。
- 任务记录 `config_id`、`prompt_hash`、`base_src`、`image_size`，异步线程池执行。
- `base_src` 保存提交时的图片地址；写回前会比对，用户如果已手动换图则不覆盖。

`GET /api/projects/{projectId}/image-jobs` 返回最近 50 条任务和当前项目版本：

```json
{
  "jobs": [
    {
      "id": "uuid",
      "sectionId": "hero",
      "path": "props.image",
      "prompt": "...",
      "baseSrc": "/presets/visual-01.svg",
      "size": "1024x1024",
      "status": "RUNNING",
      "assetId": null,
      "assetUrl": null,
      "errorMessage": null,
      "createdAt": "...",
      "updatedAt": "...",
      "finishedAt": null
    }
  ],
  "specVersion": 8
}
```

状态：`PENDING` → `RUNNING` → `SUCCEEDED` / `FAILED` / `SUPERSEDED`。

**写回规则**

- 成功：图片写入资产目录，新增 `source=AI_GENERATED` 的 `asset`，更新 PageSpec 中的 `src` 和 `assetId`，项目版本自增。
- 写回前重新读取 PageSpec；如果目标不存在，标记 `SUPERSEDED`，不覆盖页面。
- 如果图片 `prompt` 已被用户修改，`prompt_hash` 不一致，标记 `SUPERSEDED`，不覆盖当前图片。
- 失败：只把任务标记为 `FAILED` 并记录原因，PageSpec 完全不变，保留内置图或上一张图。
- 项目版本冲突时最多重试 3 次，避免和用户自动保存互相覆盖。
- 应用重启时，遗留的 `PENDING/RUNNING` 任务会被标记为失败，避免前端一直显示“生成中”。

**资产**

`asset` 表新增 `source`（`UPLOAD` / `AI_GENERATED` / `AI_TEST`）和 `prompt`。生成图同样通过 `/api/assets/{id}/content` 鉴权读取，因此静态导出 ZIP 会把生成图下载到 `assets/`。

## 11. 图片接口

### 11.1 上传

```http
POST /api/assets
Content-Type: multipart/form-data
X-XSRF-TOKEN: ...

projectId=<可选>
file=<二进制>
```

规则：

- 只允许 `image/png`、`image/jpeg`、`image/webp`、`image/gif`。
- 单文件最大 8MB。
- 校验 MIME 类型；MIME 由客户端提供，服务端未做文件头魔数校验。
- 如果传 `projectId`，必须是当前用户的项目。
- 存储路径：`{APP_STORAGE_ROOT}/{ownerId}/{uuid}.{ext}`。
- 数据库保存原文件名、MIME、字节数、宽高。
- `ImageIO` 读取宽高；WebP 可能读不到，宽高允许为空。

响应：

```json
{
  "id": "uuid",
  "url": "/api/assets/uuid/content",
  "name": "cover.png",
  "mimeType": "image/png",
  "size": 12345,
  "width": 1200,
  "height": 800
}
```

### 11.2 读取

```http
GET /api/assets/{assetId}/content
```

- 必须登录。
- 只能读取自己上传的图片。
- `Content-Type` 使用数据库中的 MIME。
- `Cache-Control: private, max-age=3600`。
- 文件不存在返回 `404`。

## 12. 校验与异常

### 12.1 常见错误码

| code | 状态 | 含义 |
| --- | --- | --- |
| `VALIDATION_ERROR` | 400 | DTO 字段校验失败 |
| `INVALID_PAGE_SPEC` | 400 | PageSpec 结构/主题非法 |
| `AI_PATCH_INVALID` | 502 | AI Patch 数组索引非法 |
| `AI_CONFIG_NOT_FOUND` | 404 | AI 配置不存在或不属于当前用户 |
| `AI_PROVIDER_INVALID` | 400 | 不支持的 AI 服务商 |
| `AI_BASE_URL_INVALID` | 400 | Base URL 不是 http/https |
| `IMAGE_AI_CONFIG_NOT_FOUND` | 404 | 图像 AI 配置不存在或不属于当前用户 |
| `IMAGE_AI_NOT_CONFIGURED` | 400 | 还没有默认图像 AI |
| `IMAGE_PROVIDER_UNSUPPORTED` | 400 | 不支持的图像协议 |
| `IMAGE_AI_BASE_URL_INVALID` | 400 | 图像 Base URL 不是 http/https |
| `IMAGE_SIZE_UNSUPPORTED` | 400 | 不支持的图片尺寸 |
| `IMAGE_TARGET_NOT_FOUND` | 400 | PageSpec 中找不到目标图片 |
| `IMAGE_PROMPT_REQUIRED` | 400 | 图片没有提示词 |
| `IMAGE_PROMPT_TOO_LONG` | 400 | 提示词超过 1500 字符 |
| `IMAGE_JOB_ALREADY_RUNNING` | 409 | 该图片已有进行中的任务 |
| `VERSION_CONFLICT` | 409 | 草稿版本冲突 |
| `FILE_TOO_LARGE` | 413 | 上传超限 |
| `INTERNAL_ERROR` | 500 | 未预期异常 |
| 无 code 的 401 | 401 | Spring Security 入口点 |
| 无 code 的 403 | 403 | Spring Security 拒绝/CSRF |

### 12.2 异常处理

`GlobalExceptionHandler` 统一处理：

- `ApiException`：业务错误，带状态码和 code。
- `MethodArgumentNotValidException`：取第一条字段错误消息。
- `MaxUploadSizeExceededException`：413。
- 其他 `Exception`：500。

**注意**：`AiProviderException` 继承自运行时异常，未被单独处理；在 AI 调用失败且 Mock 也失败时，会落到 500。当前 `AiService` 已用 Mock 兜底，正常情况下不会触发。

## 13. 当前后端限制

- Session 存在应用内存，重启掉登录，多实例不共享。
- 没有限流、验证码、登录失败次数限制。
- 邮箱注册没有邮件验证。
- 没有权限角色，所有登录用户只有 `ROLE_USER`。
- 项目列表返回完整 spec，项目多时响应体会偏大。
- 手工保存没有历史快照。
- 删除项目不删除物理图片文件。
- 对话接口没有基线版本检查。
- AI 调用没有超时重试和熔断，只有单次请求 + Mock 降级。
- 用户 AI 配置没有团队共享、配额、用量统计和模型列表拉取。
- API Key 只做了应用层加密；生产还应配合磁盘加密、密钥托管和审计日志。
- 图像任务只支持单张生成，没有批量取消、重试队列、失败退避和并发配额。
- 任务状态通过前端 2.5s 轮询，不使用 SSE/WebSocket；多实例部署时任务只会在接收请求的实例上执行。
- 图像测试图和生成图都会留在 `ASSET` 和上传目录，没有自动清理策略。
- 图片提示词和尺寸上限固定，不支持每个模型单独的能力声明。

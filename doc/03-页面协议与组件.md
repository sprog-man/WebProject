# 03 · 页面协议与组件体系

## 1. PageSpec 是什么

`PageSpec` 是 AI、编辑器、后端校验和静态导出共用的页面数据协议。它是一个 JSON 对象，描述：

- 页面元信息（标题、描述）。
- 全局主题（模式、强调色、字号、字体、圆角、间距）。
- 区块列表（导航、首屏、画廊、数据、CTA、页脚）。
- 字段元信息（当前用于记录用户修改来源）。

AI 不生成 HTML；HTML 由 `PageRenderer` 根据 `PageSpec` 渲染。

## 2. 顶层结构

```json
{
  "version": 1,
  "meta": {
    "title": "Aurora 品牌官网",
    "description": "一句话页面描述"
  },
  "theme": {
    "mode": "ink",
    "accent": "#ff6b3d",
    "titleScale": 100,
    "bodyScale": 100,
    "radius": 18,
    "font": "serif",
    "spacing": 100
  },
  "sections": [],
  "fieldMeta": {}
}
```

### 2.1 字段说明

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `version` | number | 页面协议版本，当前固定为 `1`；不是项目保存版本号 |
| `meta.title` | string | 页面标题，最长 160 |
| `meta.description` | string? | 页面描述，导出时写入 `<meta name="description">` |
| `theme` | ThemeSpec | 全局主题变量 |
| `sections` | SectionSpec[] | 区块列表，最多 12 个 |
| `fieldMeta` | object? | 字段元数据，键为 `sectionId.path`，值可含 `source`、`locked` |

### 2.2 两个 version 不要混淆

| 名称 | 位置 | 用途 |
| --- | --- | --- |
| `spec.version` | `PageSpec.version` | 页面数据协议版本，当前固定 `1`，由 `PageSpecValidator` 要求 ≥ 1 |
| `project.version` | `Project.version` | JPA `@Version` 乐观锁版本，新建项目为 `0`，每次保存/AI 修改后自增 |
| `revisionNumber` | `project_revision` / 消息 | AI 修改快照序号，从 1 开始；手工保存目前不产生快照 |

## 3. 主题 ThemeSpec

| 字段 | 类型 | 范围/枚举 | 作用 |
| --- | --- | --- | --- |
| `mode` | string | `ink` / `paper` / `forest` | 午夜 / 纸张 / 森林三套底色和文字色 |
| `accent` | string | `#RRGGBB` | 强调色，按钮、高亮、标签 |
| `titleScale` | number | 60–160 | 标题字号百分比 |
| `bodyScale` | number | 60–160 | 正文字号百分比 |
| `radius` | number | 0–40 | 圆角像素 |
| `font` | string | `serif` / `sans` | 编辑感衬线 / 现代无衬线 |
| `spacing` | number | 60–160 | 区块垂直间距百分比 |

渲染器将主题转换为 CSS 变量：

```text
--accent      = theme.accent
--title-scale = theme.titleScale / 100
--body-scale  = theme.bodyScale / 100
--radius      = theme.radius + "px"
--space       = theme.spacing / 100
```

`page-root` 同时带 `data-mode` 和 `data-font`，由 `page.css` 控制配色和字体。

## 4. SectionSpec 通用结构

```json
{
  "id": "hero",
  "component": "hero.split",
  "props": {},
  "layout": {}
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 区块唯一 id，建议小写英文短横线；服务端限制 ≤ 60 且不可重复 |
| `component` | string | 必须是组件白名单中的值 |
| `props` | object | 组件内容，必须为对象 |
| `layout` | object? | 组件布局参数，可选 |

## 5. 组件清单

### 5.1 `nav.basic` 顶部导航

**props**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `brand` | string | 品牌名 |
| `links` | string[] | 导航链接文字 |
| `note` | string | 右侧备注，如 `EST. 2018 · SHANGHAI` |

**可编辑字段**

- `props.brand`：画布行内编辑。
- `props.note`：画布行内编辑。

**当前限制**：`props.links` 在渲染器里只读展示，前端没有逐项编辑入口；需要 AI 修改或后续补充属性面板。

### 5.2 `hero.split` 首屏

**props**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `eyebrow` | string | 眉题 |
| `title` | string | 主标题，支持换行 |
| `subtitle` | string | 副标题，支持换行 |
| `ctaLabel` | string | 主按钮文案 |
| `secondaryLabel` | string | 次按钮文案 |
| `image` | ImageRef | 首屏主图 |
| `mediaLabel` | string? | 图片下方标签，默认 `Aurora / 2026`；当前不可直接编辑 |

**layout**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `align` | `left` / `center` | 文字对齐 |
| `mediaSide` | `left` / `right` | 图片在左/右 |

**可编辑字段**

- 文字：`props.eyebrow`、`props.title`、`props.subtitle`、`props.ctaLabel`、`props.secondaryLabel`。
- 图片：`props.image`。
- 布局：`align`、`mediaSide`（属性面板）。

## 6. ImageRef 图片引用

```json
{
  "src": "/presets/visual-01.svg",
  "alt": "图片说明",
  "fit": "cover",
  "assetId": "可选，上传图片的资产 id"
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `src` | string | 图片地址。内置图 `/presets/...`，上传图 `/api/assets/{id}/content` |
| `alt` | string? | 无障碍说明和图片说明 |
| `fit` | `cover` / `contain` | 填满裁剪 / 完整显示 |
| `assetId` | string? | 上传资产 id，便于识别来源 |

**内置图片**

| 路径 | 名称 |
| --- | --- |
| `/presets/visual-01.svg` | 暖光球体 |
| `/presets/visual-02.svg` | 金属拱门 |
| `/presets/visual-03.svg` | 深林切面 |
| `/presets/visual-04.svg` | 柔雾流体 |
| `/presets/visual-05.svg` | 日光网格 |

AI 系统提示词当前列出 visual-01 至 visual-04；visual-05 可以在图片面板手工选择，但 AI 生成时不一定使用。

## 7. 服务端校验规则

`PageSpecValidator` 在保存草稿和 AI 修改后执行，主要规则：

- 根节点必须是 JSON 对象。
- `version` 必须是可转 int 且 ≥ 1。
- `meta` 必须是对象，`meta.title` 必须是字符串，长度 ≤ 160。
- `theme` 必须是对象：
  - `mode` ∈ `ink/paper/forest`
  - `accent` 必须匹配 `^#[0-9a-fA-F]{6}$`
  - `titleScale`、`bodyScale`、`spacing` 在 60–160
  - `radius` 在 0–40
  - `font` ∈ `serif/sans`
- `sections` 必须是数组，最多 12 个。
- 每个 section：
  - 必须是对象。
  - `id` 非空、≤ 60、不可重复。
  - `component` 必须在白名单中。
  - `props` 必须是对象。
  - `layout` 如果存在必须是对象。
- `fieldMeta` 如果存在必须是对象。

校验失败返回：

```json
{
  "code": "INVALID_PAGE_SPEC",
  "message": "具体错误信息",
  "timestamp": "2026-11-10T..."
}
```

HTTP 状态码为 `400`。

## 8. AI JSON Patch 协议

编辑模式下，AI 返回：

```json
{
  "reply": "已经同步到画布：标题字号 110%。",
  "patches": [
    {
      "op": "replace",
      "path": "/theme/titleScale",
      "value": 110
    }
  ]
}
```

### 8.1 允许的操作

- `replace`
- `add`
- `remove`

### 8.2 允许的路径前缀

- `/theme`
- `/meta`
- `/sections`

禁止：

- 不以 `/` 开头。
- `/fieldMeta` 及其子路径。
- 其他顶层字段。
- 不支持的数组索引。
- `replace` 时索引超出数组范围。

### 8.3 应用流程

```text
currentSpec.deepCopy()
  → 逐条检查 op/path
  → 解析父路径
  → 对象字段 set/remove
  → 数组索引 set/add/remove
  → 得到 nextSpec
  → PageSpecValidator.validate(nextSpec)
  → changed = !nextSpec.equals(currentSpec)
```

Patch 失败会抛出 AI 异常，由 `AiService` 决定是否降级 Mock。

## 9. 默认页面模板

`src/main/resources/ai/default-page.json` 是完整示例页面，包含：

- 导航：`AURORA` + 三个链接 + 上海备注。
- 首屏：大字号标题、副标题、双按钮、首屏图。
- 画廊：3 个作品项。
- 数据条：3 个数据。
- CTA：行动号召。
- 页脚：品牌、备注、版权。

`PageSpecProvider` 提供：

- `defaultSpec()`：深拷贝默认模板，供 Mock 生成和示例项目使用。
- `blankSpec(title)`：只包含元信息和主题、空 sections，用于新建项目。

## 10. 可编辑字段的现状与后续

当前可编辑字段是在 `PageRenderer` 的各个组件函数中直接声明的：

```text
EditableText props:
  value / sectionId / path / label / multiline / ...
EditableImage props:
  image / sectionId / path / label / ...
```

优点：

- 实现直接，字段与 UI 绑定紧密。
- 不需要解析 DOM。

限制：

- 没有独立、可枚举的组件注册表。
- 新增组件时要同时改渲染器、校验器、提示词、图片收集逻辑。
- 属性面板的布局分支按组件名硬编码。

后续建议抽出统一的组件注册表，声明：

```text
component
displayName
defaultProps
editableFields[]
imageFields[]
layoutSchema
renderer
```

这样可以让 AI、校验、属性面板和导出共享同一份组件元数据。

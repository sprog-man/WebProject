# 07 · 数据模型与安全

> 当前实际连接的是 H2 还是 PostgreSQL，以及完整的切换步骤，见 [10-数据库设计与当前状态.md](./10-数据库设计与当前状态.md)。截至 2026-11-12，应用仍使用 H2，PostgreSQL 库已创建但尚未执行迁移。

## 1. 数据模型概览

```text
app_user 1 ─── n project 1 ─── n project_revision
   │                │
   │                └── n chat_message
   │
   ├── n ai_config
   │
   └── n asset ──── optional project_id
```

- 用户拥有多个项目。
- 项目拥有多个 AI 快照和对话消息。
- 用户拥有多个 AI 配置，但最多一个默认配置。
- 图片资产归属于用户，可关联项目。
- 删除项目会级联删除快照和消息；图片元数据保留，`project_id` 置空。
- 删除用户会级联删除其 AI 配置。

## 2. 数据库表

Flyway 迁移：

- `V1__init.sql`：用户、项目、快照、消息、资产。
- `V2__ai_config.sql`：用户 AI 配置。

### 2.1 `app_user`

| 列 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | UUID | PK | 用户 id |
| `email` | VARCHAR(255) | NOT NULL UNIQUE | 登录邮箱，统一小写 |
| `password_hash` | VARCHAR(255) | NOT NULL | BCrypt 哈希 |
| `display_name` | VARCHAR(80) | NOT NULL | 昵称 |
| `created_at` | TIMESTAMPTZ | NOT NULL | 创建时间 |
| `updated_at` | TIMESTAMPTZ | NOT NULL | 更新时间 |

对应实体：`com.xiaoliu.webporduce.user.UserAccount`。

### 2.2 `project`

| 列 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | UUID | PK | 项目 id |
| `owner_id` | UUID | NOT NULL, FK → app_user | 所有者 |
| `name` | VARCHAR(120) | NOT NULL | 项目名 |
| `spec_json` | TEXT | NOT NULL | PageSpec JSON |
| `version` | BIGINT | NOT NULL DEFAULT 0 | JPA 乐观锁版本 |
| `created_at` | TIMESTAMPTZ | NOT NULL | 创建时间 |
| `updated_at` | TIMESTAMPTZ | NOT NULL | 更新时间 |

索引：

- `idx_project_owner_updated (owner_id, updated_at DESC)`。

外键：

- `owner_id → app_user(id) ON DELETE CASCADE`。

实体：`com.xiaoliu.webporduce.project.Project`。

### 2.3 `project_revision`

| 列 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | UUID | PK | 快照 id |
| `project_id` | UUID | NOT NULL, FK → project | 所属项目 |
| `revision_number` | BIGINT | NOT NULL | 项目内递增序号 |
| `spec_json` | TEXT | NOT NULL | 完整 PageSpec |
| `source` | VARCHAR(24) | NOT NULL | `AI` / `DEMO` |
| `summary` | VARCHAR(255) | NULL | 变更摘要 |
| `created_at` | TIMESTAMPTZ | NOT NULL | 创建时间 |

约束：

- `UNIQUE (project_id, revision_number)`。
- `project_id → project(id) ON DELETE CASCADE`。

索引：

- `idx_revision_project (project_id, revision_number DESC)`。

**当前行为**：

- 示例数据写入 `source=DEMO`、`revision_number=1`。
- AI 每次产生实际改动时写入 `source=AI`，序号 +1。
- 手工保存不写快照。
- 前端暂未提供历史列表和恢复。

### 2.4 `chat_message`

| 列 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | UUID | PK | 消息 id |
| `project_id` | UUID | NOT NULL, FK → project | 所属项目 |
| `role` | VARCHAR(24) | NOT NULL | `USER` / `ASSISTANT` |
| `content` | TEXT | NOT NULL | 消息正文 |
| `revision_number` | BIGINT | NULL | 关联的 AI 快照号 |
| `created_at` | TIMESTAMPTZ | NOT NULL | 创建时间 |

索引：

- `idx_message_project_created (project_id, created_at)`。

外键：

- `project_id → project(id) ON DELETE CASCADE`。

实体：`com.xiaoliu.webporduce.chat.ChatMessage`。

### 2.5 `ai_config`

| 列 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | UUID | PK | 配置 id |
| `owner_id` | UUID | NOT NULL, FK → app_user | 所属用户 |
| `name` | VARCHAR(80) | NOT NULL | 配置名称 |
| `provider_type` | VARCHAR(32) | NOT NULL | `OPENAI_COMPATIBLE` / `ANTHROPIC` / `GEMINI` |
| `base_url` | VARCHAR(500) | NOT NULL | 服务地址 |
| `model` | VARCHAR(160) | NOT NULL | 模型名 |
| `api_key_encrypted` | TEXT | NOT NULL | AES-GCM 密文（Base64） |
| `api_key_hint` | VARCHAR(16) | NULL | 末四位提示 |
| `is_default` | BOOLEAN | NOT NULL DEFAULT FALSE | 是否默认 |
| `created_at` | TIMESTAMPTZ | NOT NULL | 创建时间 |
| `updated_at` | TIMESTAMPTZ | NOT NULL | 更新时间 |

索引：

- `idx_ai_config_owner (owner_id, created_at)`。

外键：

- `owner_id → app_user(id) ON DELETE CASCADE`。

实体：`com.xiaoliu.webporduce.ai.AiConfig`。

**当前行为**：

- 每个用户最多一个 `is_default=true`；由服务层在设置默认时清除其他默认标记。
- 新增第一个配置自动设为默认。
- 删除默认配置后，自动把最早创建的剩余配置设为默认。
- 列表接口不返回密文，只返回 `keyHint` 和 `hasApiKey`。

### 2.6 `asset`

| 列 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | UUID | PK | 资产 id |
| `owner_id` | UUID | NOT NULL, FK → app_user | 上传者 |
| `project_id` | UUID | NULL, FK → project | 可选关联项目 |
| `original_name` | VARCHAR(255) | NOT NULL | 原文件名（已清理非法字符） |
| `storage_key` | VARCHAR(255) | NOT NULL | 相对存储路径 |
| `mime_type` | VARCHAR(100) | NOT NULL | MIME 类型 |
| `byte_size` | BIGINT | NOT NULL | 字节数 |
| `width` | INTEGER | NULL | 宽 |
| `height` | INTEGER | NULL | 高 |
| `created_at` | TIMESTAMPTZ | NOT NULL | 上传时间 |

索引：

- `idx_asset_owner (owner_id, created_at DESC)`。

外键：

- `owner_id → app_user(id) ON DELETE CASCADE`。
- `project_id → project(id) ON DELETE SET NULL`。

存储：

```text
{APP_STORAGE_ROOT}/{ownerId}/{uuid}.{ext}
```

## 3. 实体与字段细节

### 3.1 `UserAccount`

- 构造时生成 UUID。
- 邮箱唯一，注册时统一小写。
- 密码只保存 BCrypt 哈希。
- `@PrePersist` 设置创建/更新时间，`@PreUpdate` 更新时间。
- 没有角色字段；所有用户由 `AppUserPrincipal` 赋予 `ROLE_USER`。

### 3.2 `Project`

- `@Version` 标注 `version`。
- 新建时 `version = 0`。
- `updateSpec` 只更新 JSON，不直接改版本；JPA 在 flush 时自增。
- `@PrePersist` 设置 id 和时间。
- `@PreUpdate` 更新 `updatedAt`。
- 没有软删除。

### 3.3 `ProjectRevision`

- 不可变快照，没有更新方法。
- `revision_number` 由服务层查询当前最大值 +1。
- 没有数据库序列，高并发下可能冲突；唯一约束会阻止重复，但会报错。
- 目前无分页查询接口。

### 3.4 `ChatMessage`

- `role` 存大写枚举名，`MessageResponse` 转小写返回前端。
- 支持传入自定义 `createdAt`，示例数据用它构造前后相隔 2 秒的消息。
- `revisionNumber` 可为空。

### 3.5 `Asset`

- `storage_key` 使用 `ownerId/uuid.ext`，避免文件名冲突。
- 上传时校验最终路径必须仍在 `storageRoot` 下，防止路径穿越。
- 原文件名会替换 `\ / : * ? " < > |` 为 `_`。
- 宽高通过 `ImageIO` 读取；WebP 可能为空。

### 3.6 `AiConfig`

- API Key 通过 `AiConfigCryptoService` 加密后存入 `api_key_encrypted`。
- 加密算法：AES/GCM/NoPadding，随机 12 字节 IV，128-bit tag。
- 密钥材料来自 `APP_AI_ENCRYPTION_KEY`，SHA-256 派生 256-bit AES Key。
- `api_key_hint` 只保存末四位；长度不足 4 的 Key 保存 `••••`。
- 修改配置时前端不回填明文 Key；留空表示保留原密文。
- 服务端内部通过 `AiRuntimeConfig` 短暂持有解密后的 Key，不写入日志或响应。

## 4. 版本与并发

### 4.1 三层版本

| 版本 | 存储 | 作用 |
| --- | --- | --- |
| 页面协议版本 | `spec.version` | 当前固定 1 |
| 项目乐观锁版本 | `project.version` | 每次保存/AI 更新自增 |
| AI 快照号 | `project_revision.revision_number` | 每次 AI 改动 +1 |

### 4.2 草稿保存

```text
客户端携带上次加载的 project.version
  → 服务端比较
  → 不一致：409，不覆盖
  → 一致：更新 spec，JPA 自增
```

这是「先检查再更新」，同时 JPA `@Version` 在 flush 时提供第二道保护。若两个请求同时通过检查，后提交者可能触发 `OptimisticLockException`，但当前没有为该异常单独映射为 409；可能落到 500。

### 4.3 AI 修改

- 对话接口不接收版本号。
- `complete` 重新读取项目并更新。
- 多标签并发可能覆盖。
- 前端发送前会先保存当前草稿，但无法防止两个标签同时和 AI 交互。

## 5. 认证设计

### 5.1 注册

```text
POST /api/auth/register
  → 校验 DTO
  → 邮箱 trim + lowercase
  → 检查重复
  → BCrypt 编码密码
  → 保存 UserAccount
  → 可选创建示例项目
  → 自动认证并写 Session
```

### 5.2 登录

```text
POST /api/auth/login
  → AuthenticationManager
  → AppUserDetailsService 按 email 查询
  → BCrypt 比对
  → 写入 SecurityContext
  → 保存到 HttpSession
```

失败统一提示「邮箱或密码不正确」，不区分用户不存在或密码错误。

### 5.3 Session

- 使用 `HttpSessionSecurityContextRepository`。
- 默认 Tomcat 内存 Session。
- 有效期 7 天。
- Cookie `http-only=true`、`same-site=lax`。
- 生产可设置 `secure=true`。
- 退出调用 `SecurityContextLogoutHandler`。

**限制**：

- 应用重启后 Session 丢失。
- 多实例部署必须使用 Spring Session JDBC/Redis 或粘性会话。
- 没有并发登录限制和会话列表。

### 5.4 CSRF

- Cookie 存储 Token，`HttpOnly=false` 让前端可读。
- 前端发送 `X-XSRF-TOKEN`。
- 非 GET/HEAD/OPTIONS 必须带 Token。
- 登录/注册接口本身也受 CSRF 保护，所以前端启动时先请求 `/api/auth/csrf`。
- H2 控制台忽略 CSRF，仅开发使用。

## 6. 授权与资源边界

### 6.1 项目

所有项目接口都调用 `CurrentUser.require().getId()`，再通过：

```text
findByIdAndOwnerId(projectId, ownerId)
```

查询。不是自己的项目返回 `404`，避免暴露存在性。

### 6.2 图片

- 上传：可选 `projectId` 会校验归属。
- 读取：`findByIdAndOwnerId(assetId, ownerId)`。
- 静态路径：拼接后检查 `startsWith(storageRoot)`。
- 图片 URL 需要登录才能访问。

### 6.3 AI 配置

- 所有 `/api/ai/**` 都要求登录。
- 查询/修改/删除都使用 `findByIdAndOwnerId(configId, ownerId)`。
- 不是自己的配置返回 `404`，避免暴露存在性。
- 对话时只解析当前用户的默认配置，不会读取其他用户的配置。
- 服务端 DeepSeek 兜底只从环境变量读取，不属于任何用户。

### 6.4 静态资源

以下路径匿名可访问：

- `/`
- `/index.html`
- `/assets/**`
- `/presets/**`
- `/favicon.ico`
- `/error`

其他 `/api/**` 需要认证。

## 7. 密码与敏感数据

- 密码使用 BCrypt。
- 不保存明文密码。
- 不在日志中输出用户密码。
- 用户 AI API Key 使用 AES-GCM 加密后落库，接口只返回末四位提示。
- 服务端 DeepSeek API Key 只从环境变量读取。
- `APP_AI_ENCRYPTION_KEY` 生产环境必须通过 Secret Manager 或部署平台密钥注入，不能提交到 Git。
- 错误响应不返回堆栈。
- API Key 不应出现在 URL、前端 localStorage、日志或 Git 历史中。

## 8. 上传安全

当前措施：

- 限制 MIME 类型。
- 限制 8MB。
- 文件名清理。
- 存储路径使用随机 UUID。
- 路径穿越检查。
- 读取需要登录和所有权。
- 内容类型按数据库 MIME 返回。

待加强：

- 校验文件头魔数，不只看客户端 MIME。
- 图片重新编码，剥离 EXIF 和潜在脚本。
- 限制像素尺寸和压缩炸弹。
- 对 SVG 上传目前不支持（只支持位图），避免脚本风险。
- 生产使用对象存储私有桶 + 签名 URL。
- 定期清理未被引用的资产。

## 9. 安全风险清单

| 风险 | 级别 | 说明 | 建议 |
| --- | --- | --- | --- |
| 会话仅内存 | 中 | 重启掉登录，多实例不共享 | Spring Session JDBC/Redis |
| 无登录限流 | 中 | 可暴力尝试密码 | 限流、验证码、锁定 |
| 无邮箱验证 | 低 | 可注册任意邮箱 | 邮件验证 |
| 无角色权限 | 低 | 所有用户同权限 | 团队角色模型 |
| 上传只校验 MIME | 中 | 可伪造 Content-Type | 魔数/重编码 |
| 本地文件存储 | 中 | 扩容和备份困难 | 对象存储 |
| AI 接口无限流 | 中 | 可能被刷额度 | 用户级限流、配额 |
| 用户 Base URL 可 SSRF | 高 | 服务端会请求用户填写的任意地址，可能访问内网 | 生产限制域名/IP 白名单，或通过独立出站代理 |
| API Key 密文泄露 | 高 | 加密密钥同时泄露可解密 | 密钥托管、轮换、最小权限 |
| 加密密钥丢失 | 高 | 旧 Key 无法解密 | 备份密钥；更换后要求重新保存 Key |
| 用户配置未隔离 | 高 | 越权读取他人 Key | 所有查询带 owner_id，已实现 |
| 对话无版本校验 | 中 | 多标签覆盖 | expectedVersion |
| 删除不清理文件 | 低 | 存储泄漏 | 定时任务 |
| H2 控制台开发开放 | 低 | 生产必须关闭 | prod 不启用 |
| CSRF Cookie 可读 | 低 | XSS 可读 Token | CSP、XSS 防护 |
| 无 CSP | 中 | XSS 风险放大 | 配置 Content-Security-Policy |

## 10. 生产安全基线

上线前至少完成：

- 强制 HTTPS，`SESSION_COOKIE_SECURE=true`。
- 必须设置高熵 `APP_AI_ENCRYPTION_KEY`，并纳入密钥托管和备份。
- 反向代理设置安全 Header。
- 数据库使用独立账号和强密码。
- 不暴露 H2 控制台。
- 限制 `/actuator`（如果启用）。
- 配置 CSP、X-Content-Type-Options、Referrer-Policy。
- 上传目录最小权限。
- 定期备份 PostgreSQL 和上传卷。
- 配置日志脱敏和错误监控。
- 对 AI 与上传接口做限流。
- 依赖漏洞扫描。

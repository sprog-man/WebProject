# 06 · AI 能力设计

## 1. 设计目标

AI 在 Aster 中负责两件事：

1. **生成**：用户描述需求，返回完整、可编辑的 PageSpec。
2. **编辑**：用户提出局部修改，返回最小 JSON Patch，而不是整页重生成。

AI 不直接生成 HTML、CSS 或 JavaScript。它只能使用固定组件库和受控字段。

## 2. 模式选择

`ChatService.send` 根据页面状态和用户文本决定模式：

```text
如果 sections 为空
  → generate

否则如果用户文本包含「重新生成」「换一版」「重做」
  → generate

否则
  → edit
```

这意味着：

- 新项目第一次对话一定生成完整页面。
- 已有页面默认局部修改。
- 用户明确要求换一版时才整页重生成。

## 3. Provider 架构

```text
AiService
├─ 用户默认 AiConfig
│  └─ AiProviderFactory
│     ├─ OpenAiCompatibleProvider
│     ├─ AnthropicProvider
│     └─ GeminiProvider
├─ 服务端 DeepSeek 兜底（可选）
└─ MockAiProvider      永远可用
```

接口：

```text
AiProvider
├─ name()
├─ available()
├─ generate(projectName, currentSpec, message)
├─ edit(currentSpec, message)
└─ testConnection()
```

公共的生成 / 编辑 / JSON 解析逻辑在 `AbstractJsonAiProvider`，具体 Provider 只实现一次模型 HTTP 调用。

返回 `AiResult`：

| 字段 | 说明 |
| --- | --- |
| `reply` | 展示给用户的中文说明 |
| `spec` | 新的 PageSpec |
| `changed` | 是否实际改变页面 |
| `provider` | 配置名称 / `mock` / `mock-fallback` |

## 4. Provider 选择与降级

`AiService.runWithFallback` 按以下优先级选择：

```text
1. 当前用户默认 AI 配置
   成功 → 返回真实模型结果
   失败 → Mock，返回 mock-fallback，并提示检查 AI 设置

2. 没有用户配置，但 AI_PROVIDER=deepseek 且 DEEPSEEK_API_KEY 非空
   成功 → 返回服务端 DeepSeek 结果
   失败 → Mock，返回 mock-fallback

3. 其他情况
   直接 Mock
```

用户配置保存在 `ai_config` 表，每个用户可以有多个配置，但最多一个 `is_default=true`。对话时只读取默认配置。

降级说明：

```text
你配置的 AI 服务暂时没有连通，我先用本地演示模式完成了这次调整。

可以到「AI 设置」里点一次测试连接，确认 Base URL、模型名和 API Key。

<Mock 的原始回复>
```

降级行为的设计目的：

- 外部模型不可用时，页面仍然可以继续编辑。
- 用户在对话中能明确看到这次是本地演示模式。
- 不会因为 AI 服务故障让整个编辑器不可用。

**风险**：降级后的修改可能和用户真实意图差距较大。用户应被明确提示，并可以撤销。

## 5. Mock 模式

Mock 不是随机占位，而是有固定规则的本地演示：

### 5.1 生成

- 使用 `default-page.json` 作为基础页面。
- 把页面标题替换为项目名。
- 根据关键词做定制，并替换组件结构：
  - 含「咖啡」→ 品牌 `MORNING`，`paper` 主题，画廊替换为 `menu.list` 咖啡单。
  - 含「奶茶 / 茶饮 / 餐饮 / 甜品 / 烘焙」→ 品牌 `SHANLAN`，`candy` 主题，画廊替换为 `menu.list` 茶单。
  - 含「摄影」或「作品集」→ 品牌 `FRAME`，`paper` 主题，首屏 `full`，画廊 `masonry`。
  - 含「AI」「人工智能」「科技」→ 品牌 `NOVA`，`ocean` 主题，画廊替换为 `feature.cards`。
- 其他情况保留 Aurora 默认页面，但仍会由设计差异兜底补首屏/画廊版式。

### 5.2 编辑

支持的指令：

| 用户说法 | Mock 行为 |
| --- | --- |
| 含「紫 / violet」 | 强调色 `#9d8cff` |
| 含「青柠 / 绿」 | 强调色 `#c8f169` |
| 含「蓝 / cyan」 | 强调色 `#75d4e8` |
| 含「粉」 | 强调色 `#ff9db4` |
| 含「金 / 黄」 | 强调色 `#e9c46a` |
| 含「暖 / 橘 / 橙 / 红」 | 强调色 `#ff6b3d` |
| 含「森林 / forest」 | 主题 `forest` |
| 含「奶油 / 浅色 / 亮色 / 纸张」 | 主题 `paper` |
| 含「午夜 / 深色 / 暗色」 | 主题 `ink` |
| 含「大一点 / 更大 / 大字号」 | 标题字号 +10，最多 125 |
| 含「小一点 / 更小」 | 标题字号 -10，最少 80 |
| 含「居中」 | 首屏 `layout.align = center` |
| 含「左对齐 / 靠左」 | 首屏 `layout.align = left` |
| 含「隐藏数据 / 数字」 | 删除所有 `stats.row` |
| 含「隐藏作品」 | 删除所有 `gallery.grid` |
| 含「换图 / 换一张图 / 图片换成」 | 首屏图在 `visual-01` / `visual-02` 间切换 |
| 含「标题改成/换成/改为 X」 | 修改首屏标题，最多 80 字 |
| 含「重新生成 / 换一版 / 重做」 | 返回默认页面变体：森林主题 + 紫色强调 |

未命中任何规则时：

- `changed = false`。
- 页面不变。
- 回复说明可以手工修改。

Mock 回复末尾会附加：

```text
（当前使用本地演示模型，到「AI 设置」添加自己的 AI 配置后会切换为真实生成。）
```

### 5.3 Mock 的边界

- 不理解复杂语义，只做关键词匹配。
- 只能在预设组件和版式内组合，不能生成任意 HTML 或全新组件。
- 不会真正理解品牌语气。
- 只用于演示和兜底，不代表最终生成质量。

## 6. 用户 AI 配置与协议适配

### 6.1 数据与加密

用户配置保存在 `ai_config` 表：

| 字段 | 说明 |
| --- | --- |
| `owner_id` | 配置所属用户 |
| `provider_type` | `OPENAI_COMPATIBLE` / `ANTHROPIC` / `GEMINI` |
| `base_url` | 服务地址，必须以 `http://` 或 `https://` 开头 |
| `model` | 模型名 |
| `api_key_encrypted` | AES-GCM 加密后的 API Key |
| `api_key_hint` | 末四位提示，列表接口只返回这个值 |
| `is_default` | 是否当前用户默认配置 |

- 加密密钥来自 `APP_AI_ENCRYPTION_KEY`，通过 SHA-256 派生 AES Key，每次加密生成随机 IV，密文格式为 `IV + CipherText` 的 Base64。
- 生产环境（`prod`）未配置密钥时拒绝启动；开发环境使用内置的本地回退密钥。
- API Key 不写入日志、不返回前端明文；编辑时留空表示保持原 Key。

### 6.2 OpenAI 兼容协议

适用于 OpenAI、DeepSeek、Moonshot、通义千问、智谱、OpenRouter、Groq、Ollama、vLLM 等。

- 地址：如果 Base URL 已以 `/chat/completions` 结尾则直接使用，否则拼接 `/chat/completions`。
- 方法：POST。
- Header：`Authorization: Bearer {apiKey}`（Key 为空时不发送，方便本地 Ollama）、`Content-Type: application/json`。
- Body：`model`、`messages`、`temperature`、`max_tokens=4096`、`stream=false`。
- 生成 temperature：0.7；编辑 temperature：0.35。
- 从 `choices[0].message.content` 取文本。
- 不强制发送 `response_format`，以兼容不支持 JSON Mode 的服务；依靠系统提示词和响应解析保证 JSON。
- 连接超时 20 秒，请求超时 120 秒。

### 6.3 Anthropic Messages API

- 地址：如果 Base URL 已以 `/messages` 结尾则直接使用，否则拼接 `/messages`。
- Header：`x-api-key`、`anthropic-version: 2023-06-01`。
- Body：`model`、`max_tokens=4096`、`temperature`、`system`、`messages`。
- 从 `content[]` 中拼接所有 `type=text` 的文本。
- 该协议必须有 API Key 才视为可用。

### 6.4 Gemini generateContent API

- 默认 Base URL：`https://generativelanguage.googleapis.com/v1beta`。
- 地址：`{baseUrl}/models/{model}:generateContent`；如果 Base URL 已经以 `:generateContent` 结尾则直接使用。
- Header：`x-goog-api-key`。
- Body：`system_instruction`、`contents`、`generationConfig`，其中 `responseMimeType=application/json`、`maxOutputTokens=4096`。
- 从 `candidates[0].content.parts[].text` 拼接文本。
- 该协议必须有 API Key 才视为可用。

### 6.5 测试连接

`POST /api/ai/configs/{id}/test` 会发送一次最小请求：

```text
这是一次连接测试。请只返回 JSON 对象 {"ok":true}。
```

返回：

```json
{
  "ok": true,
  "message": "连接成功，模型已正常响应",
  "latencyMs": 842,
  "model": "deepseek-chat"
}
```

失败时 `ok=false`，`message` 会保留 HTTP 状态或连接错误，前端直接在配置卡片上展示。

### 6.6 服务端 DeepSeek 兜底

```yaml
app:
  ai:
    provider: ${AI_PROVIDER:mock}
    encryption-key: ${APP_AI_ENCRYPTION_KEY:}
    deepseek:
      base-url: ${DEEPSEEK_BASE_URL:https://api.deepseek.com}
      api-key: ${DEEPSEEK_API_KEY:}
      model: ${DEEPSEEK_MODEL:deepseek-chat}
```

- 用户没有配置默认 AI 时，如果 `AI_PROVIDER=deepseek` 且 Key 非空，使用服务端 DeepSeek。
- 用户配置优先于服务端兜底。
- 两者都不可用时使用 Mock。

### 6.7 System Prompt

`src/main/resources/ai/system-prompt.txt` 定义：

- 角色：Aster，资深品牌网站设计师，只输出 JSON。
- 任务：生成 PageSpec、返回最小 Patch。
- 组件库和字段说明：导航、首屏、画廊、数据、特性卡片、菜单、引用、CTA、页脚。
- 首屏与画廊的多种布局变体。
- ImageRef 结构。
- 内置图片列表（visual-01 至 visual-09）。
- PageSpec / Section 结构。
- 生成模式输出格式。
- 编辑模式输出格式和规则。
- 行业与区块组合建议：茶饮/餐饮优先 `menu.list`，SaaS/服务优先 `feature.cards`，摄影/作品集优先 `gallery.grid`。

关键约束：

- 不输出 Markdown 代码块、HTML 或脚本。
- 不固定使用同一套区块顺序；每页 4–8 个区块。
- 每页至少使用一个非默认布局：首屏 `center/full/stack`，或画廊 `masonry/list`。
- 主题模式不默认 `ink/paper`，强调色不默认 `#ff6b3d`。
- 不照抄默认模板的 Aurora 文案、标题句式和固定三图画廊。
- 编辑只修改用户要求的部分。
- 不删除用户没有要求删除的区块。
- Patch 路径必须以 `/theme`、`/meta`、`/sections` 开头。
- 用户上传图片 `/api/assets/{id}/content` 必须保留，除非明确要求换图。
- 中文页面优先中文，品牌名可保留英文。

### 6.7.1 设计差异兜底

真实模型有时会省略 `layout.variant`，导致页面又落回默认的左右分栏首屏 + 三列网格画廊。`AiService` 在生成成功后做一次轻量后处理：

- 只处理生成结果，不处理用户局部编辑。
- 首屏没有 `variant` 且没有 `align=center` 时，根据主题模式补 `center` / `full` / `stack`。
- 画廊没有 `variant` 时，如果页面已有 `feature.cards`，补 `list`；否则 3 张以上补 `masonry` 或 `list`。
- 模型明确写了 `variant` 时尊重模型选择，不覆盖。
- Mock 兜底页面也会经过这一步，因此降级页面至少不会完全复用旧骨架。

### 6.8 生成与编辑 Prompt

生成：

```text
【模式】生成
【项目名称】...
【用户需求】...

请返回 {"reply": "...", "pageSpec": {...}}。
```

编辑：

```text
【模式】局部编辑
【当前 PageSpec】
{完整 JSON}

【用户修改要求】
...

请只返回 {"reply": "...", "patches": [...]}，不要返回完整页面。
```

### 6.9 响应解析

所有 Provider 复用 `AbstractJsonAiProvider`：

- 如果内容被 Markdown 代码块包裹，先去掉首尾围栏。
- 先直接解析 JSON。
- 失败则截取第一个 `{` 到最后一个 `}` 再解析。
- 仍失败 → `AiProviderException` → 触发 Mock 降级。

生成结果：

- 必须有 `pageSpec` 对象。
- 立即执行 `PageSpecValidator.validate`。
- 如果 `meta.title` 为空，用项目名补齐。
- 如果没有 `fieldMeta`，补空对象。

编辑结果：

- 必须有 `patches` 数组。
- 通过 `SpecPatchApplier` 应用。
- 应用后再次执行 `PageSpecValidator.validate`。
- 比较 `nextSpec` 与 `currentSpec` 判断 `changed`。

## 7. JSON Patch 安全限制

`SpecPatchApplier` 不是通用 JSON Patch 实现，而是**受限子集**：

### 7.1 允许的 op

- `replace`
- `add`
- `remove`

不支持 `move`、`copy`、`test` 等。

### 7.2 允许的 path

- `/theme`
- `/meta`
- `/sections`

拒绝：

- 不以 `/` 开头。
- `/fieldMeta` 及其子路径。
- 其他顶层字段。
- 父路径不存在。
- 非法数组索引。
- `replace` 时索引超出数组范围。

### 7.3 数组行为

- `add` 支持 `-` 追加。
- 数字索引必须在 0..size 范围内。
- `remove` 只删除有效索引。
- `replace` 不能写到 size 位置。

### 7.4 应用后校验

Patch 即使路径合法，也可能产生非法 PageSpec，例如：

- 把主题改成不支持的模式。
- 把组件改成未知类型。
- 把区块 id 改重复。
- 把 sections 改成非数组。

因此 Patch 应用后仍必须执行完整校验。校验失败会抛出 `INVALID_PAGE_SPEC`。

## 8. 持久化与消息

对话流程分两段事务：

```text
prepare:
  校验项目归属
  写 user 消息
  读取当前 spec / version

AI call:
  generate 或 edit

complete:
  重新读取项目
  校验新 spec
  更新 project.spec_json
  project.version 自增
  写 project_revision（changed 时）
  写 assistant 消息
  返回新 spec / version / revisionNumber / changed
```

`project_revision`：

- `source = AI`
- `summary` 取用户消息前 200 字。
- `revision_number` 在当前最大号上 +1。
- `spec_json` 保存修改后的完整页面。

助手消息：

- 如果 `changed`，带 `revisionNumber`。
- 如果没有改动，`revisionNumber = null`。

## 9. 失败与降级矩阵

| 场景 | 行为 |
| --- | --- |
| Mock 正常 | 返回 Mock 结果 |
| 用户默认 AI 正常 | 返回用户配置的真实模型结果 |
| 用户默认 AI 测试失败 | 配置卡片显示错误，不影响其他配置 |
| 用户默认 AI 调用失败 | fallback Mock，回复中提示检查 AI 设置 |
| 用户 AI 返回非法 JSON | fallback Mock |
| 用户 AI 返回非法 PageSpec | fallback Mock |
| 用户 AI 返回非法 Patch | fallback Mock |
| 无用户配置 + 服务端 DeepSeek 正常 | 返回服务端 DeepSeek 结果 |
| 服务端 DeepSeek 无 Key | 直接 Mock，服务端 warning |
| Mock 也异常 | 请求失败，前端提示 |
| 用户消息保存后 AI 失败 | 用户消息已持久化，页面不变 |

## 10. 提示词与用户手工修改的关系

当前策略：

- 用户手工修改会在 `fieldMeta` 中记录 `source: user`。
- AI 编辑 Prompt 会附带完整当前 PageSpec。
- System Prompt 要求「尽量保留其他已存在的文案、图片和结构」。
- 但后端不会根据 `fieldMeta` 强制阻止 AI 修改用户字段。

因此：

- 用户改过的字段仍可能被 AI 修改。
- 用户可以通过撤销恢复。
- 未来应在 Prompt 中显式列出用户锁定的字段，或在 Patch 应用时做字段级拦截。

## 11. 真实 AI 验证清单

当前已通过接口层验证：

- 三种 Provider 预设可读取。
- 新增 / 更新 / 设置默认 / 删除配置。
- 更新时留空 API Key 会保留原 Key。
- 删除默认配置后自动把最早的其他配置设为默认。
- 错误 Base URL 的测试连接返回失败，不阻塞编辑器。
- 默认配置指向不可用地址时，对话会降级 Mock 并成功写回页面。

真实模型仍需按以下顺序验证：

1. 在 `#/settings/ai` 添加真实 DeepSeek / OpenAI / Anthropic / Gemini 配置，点击测试连接。
2. 新建空白项目，发送「为独立咖啡品牌做官网首屏」。
3. 检查是否返回合法 PageSpec，页面是否可渲染。
4. 发送「把标题改成……」，检查是否只改首屏标题。
5. 发送「标题更大一点」，检查是否只改 `titleScale`。
6. 发送「隐藏数据条」，检查是否只删除 `stats.row`。
7. 上传图片后发送无关修改，检查图片是否保留。
8. 填写错误 Key，检查是否降级 Mock 并有提示。
9. 检查 `project_revision` 是否按次递增。
10. 检查对话消息和快照是否一致。

## 12. 图像生成能力

### 12.1 职责拆分

```text
文本 AI（用户默认文本配置 / 服务端 DeepSeek / Mock）
  └─ 生成 PageSpec，并为每张图片写入 prompt
       ↓ 用户在前端确认勾选
后端 ImageJobService
  ├─ 校验项目归属、目标图片、prompt
  ├─ 记录 image_job（PENDING）
  └─ imageTaskExecutor 异步执行
       ↓
ImageProviderFactory
  └─ OpenAiImageProvider（OPENAI_IMAGES）
       ↓
图片二进制 → AssetService 保存 → 更新 PageSpec → app_user 可见
```

文本 AI 不接触图像 API Key，也不直接调用图像端点；图像 Key 只在后端运行时配置中存在。

### 12.2 文本 AI 生成提示词

- `system-prompt.txt` 要求每个 `ImageRef` 必须写 `prompt`，并给出行业摄影指导要求：主体 + 场景 + 构图 + 光线 + 材质 + 色彩 + 氛围。
- 同一页多张图要有不同视角，禁止文字、Logo、水印和可识别真人。
- `MockAiProvider` 为咖啡、茶饮、摄影、AI 等行业写入与行业一致的英文提示词。
- `default-page.json` 的内置页面本身带提示词，旧项目重新生成后即可获得提示词。
- `AiService.ensureImagePrompts` 在生成后兜底：只要图片缺 `prompt`，就按行业场景和图片序号补写，保证确认弹窗里不会出现空提示词。

### 12.3 用户确认

- 文本页面生成成功后，前端自动打开「生成页面图片」面板。
- 默认只勾选首屏主图，画廊图片默认不勾选。
- 用户可以逐张修改提示词、勾选或取消勾选。
- 只有点击「生成选中图片」后，前端才调用 `POST /api/projects/{id}/image-jobs`，请求体里只包含选中的图片。
- 每张图片都可能产生真实费用，测试连接首次点击会二次确认。

### 12.4 异步任务

- 任务表 `image_job` 保存 `target_path`、`prompt`、`prompt_hash`、`image_size`、`config_id`。
- 线程池 2 个线程、队列 20，最多同时提交 5 张。
- 同一目标已有 PENDING/RUNNING 任务时拒绝重复提交。
- 前端每 2.5 秒轮询任务列表，画布图片显示“AI 正在生成图片”，面板显示进度和每张状态。
- 应用重启时遗留任务标记为失败，避免永久“生成中”。

### 12.5 成功、失败与过期

| 场景 | 行为 |
| --- | --- |
| 生成成功且 prompt 未变 | 保存资产，更新 `src`/`assetId`，任务 `SUCCEEDED` |
| 生成成功但项目已删除 | 任务 `FAILED`，不写页面 |
| 生成成功但图片位置已被删除 | 任务 `SUPERSEDED`，不覆盖页面 |
| 生成成功但 prompt 已被修改 | 任务 `SUPERSEDED`，避免旧结果覆盖新提示词 |
| 连接失败 / HTTP 非 2xx / 数据无法解析 | 任务 `FAILED`，记录真实原因，PageSpec 不变 |
| 项目版本冲突 | 最多重试 3 次，仍冲突则任务失败 |
| 应用重启 | 遗留任务 `FAILED`，页面保留原图 |

失败时页面不会出现空白或破图：原 `src` 仍然指向内置图、上传图或上一张生成图，面板展示 `errorMessage`。

### 12.6 OpenAI Images 适配

`OpenAiImageProvider` 面向 OpenAI Images 协议，兼容：

- 请求：`POST {baseUrl}/images/generations`；如果 Base URL 已含 `/images/generations` 或 `/v1`，会正确拼接。
- Body：`model`、`prompt`、`n=1`、`size`，可选 `quality`。
- Header：`Authorization: Bearer {apiKey}`；本地无 Key 服务可留空。
- 响应：优先识别 `b64_json` / `b64` / `base64` / `image_base64`，也识别 `url` / `image_url` / `image`、`data.images[]`、`output[]` 和 `data:` URL。
- 图片内容校验 PNG/JPEG/GIF/WebP 魔数，最大 8MB。
- 远程 URL 会下载为本地资产，不把第三方地址直接写进页面。
- 超时 180 秒，连接超时 15 秒，最多跟随 3xx 重定向。

首版只实现 `OPENAI_IMAGES` 一个协议；Anthropic 不提供图像生成，其他厂商需要新增适配器。

### 12.7 安全

- 图像配置 API Key 与文本 AI 共用 `AiConfigCryptoService`，AES-GCM 加密落库。
- 列表和测试响应只返回 `keyHint` 末四位，不返回明文、密文或 `apiKeyEncrypted`。
- 图像任务接口校验项目归属；`/api/assets/{id}/content` 只允许读取自己的图片。
- 远程返回的 URL 只在服务端下载，避免浏览器直连第三方和热链。

## 13. AI 设计后续改进

- 在 Prompt 中加入用户锁定字段清单。
- 让 AI 返回结构化「变更摘要」用于 UI 展示。
- 对 Patch 做字段级权限白名单。
- 增加重试、指数退避和熔断。
- 增加生成质量评估集和回归用例。
- 支持流式响应，减少等待感。
- 支持多轮上下文摘要，避免每次都传完整 PageSpec。
- 支持组件级生成（只生成某个区块）而不是整页。
- 支持 AI 解释「为什么这样改」并让用户逐条接受。

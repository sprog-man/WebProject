# 06 · AI 能力设计

## 1. 设计目标

AI 在 Aster 中负责两件事：

1. **生成**：用户描述需求，返回完整、可编辑的 PageSpec。
2. **编辑**：用户提出局部修改，返回最小 JSON Patch，而不是整页重生成。

AI 不直接生成 HTML、CSS 或 JavaScript。它只能使用固定组件库和受控字段。

## 2. 模式选择

`ChatService.send` 根据页面状态和用户文本决定模式：

```text
如果 sections 为空
  → generate

否则如果用户文本包含「重新生成」「换一版」「重做」
  → generate

否则
  → edit
```

这意味着：

- 新项目第一次对话一定生成完整页面。
- 已有页面默认局部修改。
- 用户明确要求换一版时才整页重生成。

## 3. Provider 架构

```text
AiService
├─ MockAiProvider      默认，永远可用
└─ DeepSeekAiProvider  配置 Key 后启用
```

接口：

```text
AiProvider
├─ name()
├─ available()
├─ generate(projectName, currentSpec, message)
└─ edit(currentSpec, message)
```

返回 `AiResult`：

| 字段 | 说明 |
| --- | --- |
| `reply` | 展示给用户的中文说明 |
| `spec` | 新的 PageSpec |
| `changed` | 是否实际改变页面 |
| `provider` | `mock` / `deepseek` / `mock-fallback` |

## 4. Provider 选择与降级

`AiService.runWithFallback`：

```text
if AI_PROVIDER == deepseek 且 apiKey 非空
    尝试 DeepSeek
    成功 → 返回 DeepSeek 结果
    失败 → 调用 Mock，返回 mock-fallback 结果，并附加说明
else
    直接调用 Mock
```

降级说明：

```text
模型服务暂时没有连通，我先用本地演示模式完成了这次调整。

<Mock 的原始回复>
```

降级行为的设计目的：

- 外部模型不可用时，页面仍然可以继续编辑。
- 用户在对话中能明确看到这次是本地演示模式。
- 不会因为 AI 服务故障让整个编辑器不可用。

**风险**：降级后的修改可能和用户真实意图差距较大。用户应被明确提示，并可以撤销。

## 5. Mock 模式

Mock 不是随机占位，而是有固定规则的本地演示：

### 5.1 生成

- 使用 `default-page.json` 作为基础页面。
- 把页面标题替换为项目名。
- 根据关键词做少量定制：
  - 含「咖啡」→ 品牌 `MORNING`，咖啡相关标题和描述，暖棕色强调色。
  - 含「摄影」或「作品集」→ 品牌 `FRAME`，摄影相关标题，金色强调色。
  - 含「AI」「人工智能」「科技」→ 品牌 `NOVA`，科技相关标题，青色强调色。
- 其他情况保留 Aurora 默认页面。

### 5.2 编辑

支持的指令：

| 用户说法 | Mock 行为 |
| --- | --- |
| 含「紫 / violet」 | 强调色 `#9d8cff` |
| 含「青柠 / 绿」 | 强调色 `#c8f169` |
| 含「蓝 / cyan」 | 强调色 `#75d4e8` |
| 含「粉」 | 强调色 `#ff9db4` |
| 含「金 / 黄」 | 强调色 `#e9c46a` |
| 含「暖 / 橘 / 橙 / 红」 | 强调色 `#ff6b3d` |
| 含「森林 / forest」 | 主题 `forest` |
| 含「奶油 / 浅色 / 亮色 / 纸张」 | 主题 `paper` |
| 含「午夜 / 深色 / 暗色」 | 主题 `ink` |
| 含「大一点 / 更大 / 大字号」 | 标题字号 +10，最多 125 |
| 含「小一点 / 更小」 | 标题字号 -10，最少 80 |
| 含「居中」 | 首屏 `layout.align = center` |
| 含「左对齐 / 靠左」 | 首屏 `layout.align = left` |
| 含「隐藏数据 / 数字」 | 删除所有 `stats.row` |
| 含「隐藏作品」 | 删除所有 `gallery.grid` |
| 含「换图 / 换一张图 / 图片换成」 | 首屏图在 `visual-01` / `visual-02` 间切换 |
| 含「标题改成/换成/改为 X」 | 修改首屏标题，最多 80 字 |
| 含「重新生成 / 换一版 / 重做」 | 返回默认页面变体：森林主题 + 紫色强调 |

未命中任何规则时：

- `changed = false`。
- 页面不变。
- 回复说明可以手工修改。

Mock 回复末尾会附加：

```text
（当前使用本地演示模型，配置 DEEPSEEK_API_KEY 后会切换为真实生成。）
```

### 5.3 Mock 的边界

- 不理解复杂语义，只做关键词匹配。
- 不能生成全新组件或布局。
- 不会真正理解品牌语气。
- 只用于演示和兜底，不代表最终生成质量。

## 6. DeepSeek 接入

### 6.1 配置

```yaml
app:
  ai:
    provider: ${AI_PROVIDER:mock}
    deepseek:
      base-url: ${DEEPSEEK_BASE_URL:https://api.deepseek.com}
      api-key: ${DEEPSEEK_API_KEY:}
      model: ${DEEPSEEK_MODEL:deepseek-chat}
```

启用：

```bash
AI_PROVIDER=deepseek
DEEPSEEK_API_KEY=sk-...
DEEPSEEK_MODEL=deepseek-chat
```

如果 `AI_PROVIDER=deepseek` 但 Key 为空：

- `available()` 返回 false。
- 直接使用 Mock。
- 服务端记录 warning。

### 6.2 HTTP 请求

- 地址：`{baseUrl}/chat/completions`。
- 方法：POST。
- Header：`Authorization: Bearer {apiKey}`、`Content-Type: application/json`。
- 连接超时：20 秒。
- 请求超时：120 秒。
- `stream=false`。
- `response_format.type=json_object`。
- `max_tokens=4096`。
- 生成 temperature：0.7。
- 编辑 temperature：0.35。

### 6.3 System Prompt

`src/main/resources/ai/system-prompt.txt` 定义：

- 角色：Aster，资深品牌网站设计师，只输出 JSON。
- 任务：生成 PageSpec、返回最小 Patch。
- 组件库和字段说明。
- ImageRef 结构。
- 内置图片列表。
- PageSpec / Section 结构。
- 生成模式输出格式。
- 编辑模式输出格式和规则。

关键约束：

- 不输出 Markdown 代码块、HTML 或脚本。
- 编辑只修改用户要求的部分。
- 不删除用户没有要求删除的区块。
- Patch 路径必须以 `/theme`、`/meta`、`/sections` 开头。
- 用户上传图片 `/api/assets/{id}/content` 必须保留，除非明确要求换图。
- 中文页面优先中文，品牌名可保留英文。

### 6.4 生成 Prompt

```text
【模式】生成
【项目名称】...
【用户需求】...

请返回 {"reply": "...", "pageSpec": {...}}。
```

### 6.5 编辑 Prompt

```text
【模式】局部编辑
【当前 PageSpec】
{完整 JSON}

【用户修改要求】
...

请只返回 {"reply": "...", "patches": [...]}，不要返回完整页面。
```

### 6.6 响应解析

- 从 `choices[0].message.content` 取文本。
- 如果内容被 Markdown 代码块包裹，先去掉首尾围栏。
- 先直接解析 JSON。
- 失败则截取第一个 `{` 到最后一个 `}` 再解析。
- 仍失败 → `AiProviderException` → 触发 Mock 降级。

生成结果：

- 必须有 `pageSpec` 对象。
- 立即执行 `PageSpecValidator.validate`。
- 如果 `meta.title` 为空，用项目名补齐。
- 如果没有 `fieldMeta`，补空对象。

编辑结果：

- 必须有 `patches` 数组。
- 通过 `SpecPatchApplier` 应用。
- 应用后再次执行 `PageSpecValidator.validate`。
- 比较 `nextSpec` 与 `currentSpec` 判断 `changed`。

## 7. JSON Patch 安全限制

`SpecPatchApplier` 不是通用 JSON Patch 实现，而是**受限子集**：

### 7.1 允许的 op

- `replace`
- `add`
- `remove`

不支持 `move`、`copy`、`test` 等。

### 7.2 允许的 path

- `/theme`
- `/meta`
- `/sections`

拒绝：

- 不以 `/` 开头。
- `/fieldMeta` 及其子路径。
- 其他顶层字段。
- 父路径不存在。
- 非法数组索引。
- `replace` 时索引超出数组范围。

### 7.3 数组行为

- `add` 支持 `-` 追加。
- 数字索引必须在 0..size 范围内。
- `remove` 只删除有效索引。
- `replace` 不能写到 size 位置。

### 7.4 应用后校验

Patch 即使路径合法，也可能产生非法 PageSpec，例如：

- 把主题改成不支持的模式。
- 把组件改成未知类型。
- 把区块 id 改重复。
- 把 sections 改成非数组。

因此 Patch 应用后仍必须执行完整校验。校验失败会抛出 `INVALID_PAGE_SPEC`。

## 8. 持久化与消息

对话流程分两段事务：

```text
prepare:
  校验项目归属
  写 user 消息
  读取当前 spec / version

AI call:
  generate 或 edit

complete:
  重新读取项目
  校验新 spec
  更新 project.spec_json
  project.version 自增
  写 project_revision（changed 时）
  写 assistant 消息
  返回新 spec / version / revisionNumber / changed
```

`project_revision`：

- `source = AI`
- `summary` 取用户消息前 200 字。
- `revision_number` 在当前最大号上 +1。
- `spec_json` 保存修改后的完整页面。

助手消息：

- 如果 `changed`，带 `revisionNumber`。
- 如果没有改动，`revisionNumber = null`。

## 9. 失败与降级矩阵

| 场景 | 行为 |
| --- | --- |
| Mock 正常 | 返回 Mock 结果 |
| DeepSeek 正常 | 返回 DeepSeek 结果 |
| DeepSeek 无 Key | 直接 Mock，服务端 warning |
| DeepSeek 网络失败 | fallback Mock，回复中说明 |
| DeepSeek 返回非法 JSON | fallback Mock |
| DeepSeek 返回非法 PageSpec | fallback Mock |
| DeepSeek 返回非法 Patch | fallback Mock |
| Mock 也异常 | 请求失败，前端提示 |
| 用户消息保存后 AI 失败 | 用户消息已持久化，页面不变 |

## 10. 提示词与用户手工修改的关系

当前策略：

- 用户手工修改会在 `fieldMeta` 中记录 `source: user`。
- AI 编辑 Prompt 会附带完整当前 PageSpec。
- System Prompt 要求「尽量保留其他已存在的文案、图片和结构」。
- 但后端不会根据 `fieldMeta` 强制阻止 AI 修改用户字段。

因此：

- 用户改过的字段仍可能被 AI 修改。
- 用户可以通过撤销恢复。
- 未来应在 Prompt 中显式列出用户锁定的字段，或在 Patch 应用时做字段级拦截。

## 11. 真实 DeepSeek 验证清单

当前尚未配置 Key，建议按以下顺序验证：

1. 配置 `AI_PROVIDER=deepseek`、`DEEPSEEK_API_KEY`。
2. 新建空白项目，发送「为独立咖啡品牌做官网首屏」。
3. 检查是否返回合法 PageSpec，页面是否可渲染。
4. 发送「把标题改成……」，检查是否只改首屏标题。
5. 发送「标题更大一点」，检查是否只改 `titleScale`。
6. 发送「隐藏数据条」，检查是否只删除 `stats.row`。
7. 上传图片后发送无关修改，检查图片是否保留。
8. 断网或填写错误 Key，检查是否降级 Mock 并有提示。
9. 检查 `project_revision` 是否按次递增。
10. 检查对话消息和快照是否一致。

## 12. AI 设计后续改进

- 在 Prompt 中加入用户锁定字段清单。
- 让 AI 返回结构化「变更摘要」用于 UI 展示。
- 对 Patch 做字段级权限白名单。
- 增加重试、指数退避和熔断。
- 增加生成质量评估集和回归用例。
- 支持流式响应，减少等待感。
- 支持多轮上下文摘要，避免每次都传完整 PageSpec。
- 支持组件级生成（只生成某个区块）而不是整页。
- 支持 AI 解释「为什么这样改」并让用户逐条接受。

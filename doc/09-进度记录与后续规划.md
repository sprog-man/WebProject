### 3.8 生成风格多样性改造

问题：真实模型生成不同主题时，仍然反复使用同一套 `nav → hero → gallery → stats → cta → footer` 骨架。原因不是模型供应商，而是页面协议和渲染器只提供一套固定版式：

- 只有 6 个组件，AI 没有菜单、特性卡片、评价等更适合行业的结构。
- `hero.split` 只有左文右图，`gallery.grid` 只有三列竖卡。
- 只有 `ink/paper/forest` 三套主题。
- 内置图片只有 5 张抽象图。

本轮改造：

- 组件从 6 个扩展到 9 个：新增 `feature.cards`、`menu.list`、`quote.block`。
- 首屏新增 `split/center/full/stack` 版式。
- 画廊新增 `grid/masonry/list` 版式。
- 主题从 3 套扩展到 6 套：新增 `ocean/candy/mono`。
- 内置图片从 5 张扩展到 9 张。
- System Prompt 增加行业区块组合建议，并明确禁止默认套用固定 6 段结构、固定 Aurora 文案和固定强调色。
- 属性面板支持首屏/画廊版式切换，以及特性卡片、菜单列数切换。

验证：

- `npm run build` 通过，TypeScript 检查和 Vite 构建成功，84 个模块。
- `mvnw -B -ntp -Dskip.frontend=true test` 通过，6 个测试通过（新增 3 个 Mock 生成测试）。
- 用 Agnes + `agnes-2.5-flash` 真实生成三类页面，结构已经分开：
  - 茶饮：`candy` 主题，`nav → hero.split → quote.block → menu.list → stats.row → cta → footer`，7 个区块。
  - SaaS：`mono` 主题，`nav → hero.split → feature.cards → stats.row → quote.block → cta → footer`，7 个区块。
  - 摄影：`paper` 主题；模型省略版式时，后处理补为 `hero.full + gallery.list`，5 个区块。
- 用临时 PageSpec 在浏览器中检查了新组件和版式：`feature.cards` 2/3/4 列、`menu.list` 1/2 列、`quote.block`、首屏 `full/stack`、画廊 `masonry/list` 均能正常渲染，属性面板的版式切换可用。

## 6. 已知问题与限制

### 6.1 功能限制

| 问题 | 影响 | 建议 |
| --- | --- | --- |
| 无版本历史 UI | 已有快照但用户看不到、不能恢复 | 增加历史列表、预览、恢复 |
| 手工保存不写快照 | 用户手工修改无法回溯到具体版本 | 增加手动快照或自动周期快照 |
| `fieldMeta` 未参与 AI 保护 | AI 仍可能改用户字段 | Prompt 显式列出锁定字段 + Patch 拦截 |
| 导航 links 不可编辑 | 只能通过 AI 改 | 增加链接列表编辑 |
| 首屏 mediaLabel 不可编辑 | 只能通过 AI 改 | 加入属性面板 |
| 无区块增删/排序 UI | 结构变化依赖 AI | 增加结构编辑器 |
| 对话接口无版本检查 | 多标签可能覆盖 | 请求增加 expectedVersion |
| AI 失败时写入 Mock 页面 | 用户可能误以为真实模型生成了页面 | 已显示真实失败原因；可发送“重新生成/换一版”重试 |
| 项目列表返回完整 spec | 项目多时响应大 | 摘要 DTO + 缩略图字段 |
| 删除项目不清理图片文件 | 存储残留 | 定时清理或对象存储生命周期 |
| 导出为客户端打包 | 大页面可能卡顿 | 服务端异步导出 |
| Session 内存存储 | 重启掉登录、多实例不共享 | Spring Session JDBC/Redis |
| 图像任务靠轮询 | 状态更新最多延迟 2.5s，页面后台标签可能更慢 | 后续改 SSE/WebSocket |
| 图像任务只在单实例执行 | 多实例部署时任务与轮询可能不在同一实例 | 引入队列（Redis/RabbitMQ）和共享状态 |
| 图像测试图与生成图不自动清理 | `asset` 和上传目录持续增长 | 定期清理 `AI_TEST`、孤立资产 |
| 图像模型能力写死 | 不同厂商的尺寸、质量、响应格式差异需改代码 | 增加模型能力声明和更多适配器 |
| 图像生成无费用上限 | 用户可能连续生成产生费用 | 增加配额、预算提醒和并发限制 |

### 6.2 验证缺口

| 缺口 | 风险 | 优先级 |
| --- | --- | --- |
| 真实第三方模型只验证了 Agnes | 其他 Provider 适配仍需实测 | P0 |
| Docker/PostgreSQL 未测 | 生产启动可能失败 | P0 |
| 390/900/700 窄屏未实测 | 移动端布局可能有溢出或遮挡 | P0 |
| JPG/WebP/GIF 未逐一测 | 某些格式上传失败 | P1 |
| 8MB 边界未测 | 前后端限制可能不一致 | P1 |
| 无 E2E | 回归依赖手工 | P1 |
| 无真实浏览器兼容矩阵 | Safari/Firefox 可能有问题 | P1 |

### 6.3 安全与运维缺口

- 无登录限流和验证码。
- 无邮箱验证。
- 无 CSP。
- 上传只校验 MIME，未校验文件头。
- 无对象存储。
- 无监控和告警。
- 无数据库备份脚本。
- 无 CI/CD。
- 无依赖漏洞扫描。
- 生产 Cookie Secure 需要 HTTPS 配合。
- H2 控制台必须在生产关闭。

### 6.4 工程限制

- 仓库已推送到 GitHub；文本/图像 AI 配置与图像生成功能需要在本轮一起提交。
- 前端主 chunk 约 734KB，gzip 约 223KB，未做代码分割。
- 没有统一组件注册表，新增组件需要改渲染器、校验器、提示词、属性面板、导出图片收集。
- 没有 API 版本前缀。
- 没有 OpenAPI 文档。
- 测试主要覆盖后端 API，前端交互没有自动化。
- AI 配置没有用量统计、模型列表拉取和批量导入导出。

## 8. 交付说明建议

向使用者交付时，建议说明：

9. 开发测试账号和临时数据不要用于生产。
